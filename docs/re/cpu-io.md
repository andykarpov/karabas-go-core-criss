# КРИСС CP/M: порты ввода-вывода Z80 и связи МК ЦПУ (прошивка ЦПУ 4.67)

Источник — дизассемблер `upstream/dis/cpu467.S` (`avr-objdump -m avr:51`, файл `criss.cpu.4.67/cpu.hex.bin`), для сравнения — `cpd.S` (КВУ 0.24), `vga.S` (ВГА 2023-11), `clr.S` (CLR 0.5). Все адреса — байтовые адреса флеш AVR (как в `cpu467.S`), если не сказано иное; «ОЗУ AVR 0x3F00» — адрес в пространстве данных ATmega1284P. Пометки: **[код]** — подтверждено кодом, **[дог.]** — догадка, **[док.]** — только документация.

Происхождение: разделы 0–2, 4–6, 9, 10, 13 разобраны напрямую; 3, 7, 8 (совместимость, клавиатура, прерывания), 11 (сеть) и 12 (CONOUT/ESC) — из параллельных разборов (под-агенты) с выборочной перепроверкой; перепроверенные строки помечены «[перепроверено]», прочие строки этих разделов — разбор под-агента без повторной проверки.

Связанный файл: `cpu-core.md` (таблицы опкодов, ловушки ED, BIOS) пишет другой агент.

## 1. Разбор номера порта (верхний уровень)

IN, 0x10128 [код]:

| Порт | Действие |
|---|---|
| 00–CF | номер → ОЗУ 0x0910, `jmp 0x16a08` — слой совместимости (раздел 3) |
| D0–F3 | `r21 = n − 0xD0` → 0x100B0: **чтение регистра КВУ по SPI** (раздел 2) |
| F4–FD чётный | вернуть ОЗУ AVR 0x0800+n (адрес банка) |
| F5–FD нечётный | чтение банка с автоинкрементом адреса (раздел 4) |
| FE, FF | вернуть ОЗУ 0x08FE / 0x08FF (результат последней команды) |

OUT, 0x101B2 [код]:

| Порт | Действие |
|---|---|
| 00–CF | номер → 0x0910, `jmp 0x16a0a` — слой совместимости |
| D0–F3 | A → 0x090F, `r21 = n − 0xD0` → 0x100E2: **запись регистра КВУ по SPI**. Исключение: OUT D6 игнорируется, если бит 3 байта 0x36C0 = 1 (настройка «DISABLE: P MUSIC») |
| F4–FD | A → 0x0800+n; для нечётного — ещё запись в банк с автоинкрементом |
| FE | команда внешних устройств (раздел 5); **каждая запись = команда**, параметров через FE нет — параметры берутся из банков |
| FF | команда внутренних устройств, конечный автомат с параметрами (раздел 6); итог r21 → 0x08FF |

Важно для ядра: порты D0–F3 (36 штук) в ЦПУ **не хранятся вообще** — это регистры КВУ (ОЗУ КВУ 0x08D0+(n−0xD0)). Их смысл задаёт прошивка КВУ.

## 2. Шина SPI и протоколы с другими МК

### 2.1 Выбор устройства

PORTB младшие 4 бита → 74HC138 (A0..A2 = PB0..PB2, PB3 = разрешение E3, активный 1), PB4 = /E1 (опускается `cbi PORTB,4` после настройки), PD1 = /E2 (`cbi PORTD,1` на время обмена, затем `sbi`). Документация называет бит1 «F128» и бит2 «FIRQ» — в 4.67 бит1 = CLR [код], бит2 не ставится [код, поиск по `ori`].

### 2.2 Кадры ЦПУ → КВУ (устройство Y0)

| Кадр | Байты MOSI | Ответ | Где |
|---|---|---|---|
| Чтение регистра p (p = порт − 0xD0, 0x00..0x23) | `p & 0x3F`, пауза ~45 тактов, `0xFF` | второй байт MISO = значение | 0x100B0 [код] |
| Запись регистра p | `0x40 \| p`, пауза ~15 тактов, `value` | — | 0x100E2 [код] |
| Запись в «видеопамять» (любая запись Z80 по адресу ≥ 0xF800) | `addr_hi` (0xF8..0xFF, т.е. ≥ 0xC0), `addr_lo`, `data` | — | напр. PUSH 0xE1C2–0xE218, LD (HL),r и т.д. — после каждой записи в ОЗУ: `cp r29,r6; brcs` [код] |
| Сброс приёма | `0x80` | — | обработчик КВУ 0x6A [код cpd] |

Сторона КВУ (`cpd.S`, прерывание SPI 0x44) [код]: байты пишутся подряд в r0, r1, r2 (X с 0). Бит7 первого байта — видео: после 3-го байта адрес `0x0100 + ((b0 & 7) << 8 | b1)`; запись, только если адрес < 0x08D0 (т.е. смещение 0..0x7CF = 2000 байт = 80×25). Запись в F800+2000…FFFF (FFD0–FFFF) **на экран не попадает**. Бит6 — запись регистра 0x08D0 + (b0 & 0x3F). Иначе — чтение регистра 0x08D0 + b0, байт кладётся в SPDR; если бит 5 номера (p ≥ 0x20, т.е. порты F0–F3) — регистр после чтения обнуляется («clear-on-read», это F1 COMST и F3 COMRX).

### 2.3 Экран: КВУ → ВГА

Экран (2000 байт) и регистры D0–D2 живут **в КВУ**, не в ЦПУ. Цикл КВУ 0xA00 непрерывно выдвигает содержимое экрана через PORTC (программный последовательный канал) в ВГА; на позиции курсора (сравнение адреса символа с парой D1:D2, т.е. D1:D2 = адрес в ОЗУ КВУ 0x0100+смещение) в фазе мигания (r22 — счётчик тиков 10 мс по модулю 100, cpd 0x1406–0x140E; при r22 < 0x32) подставляет код 0x00: 0,5 с символ 0, 0,5 с сам символ — **курсор = символ 0 знакогенератора**, мигание делает КВУ [код cpd 0xA08–0xA1C]. ВГА (`vga.S` 0x600) принимает 2000 байт в своё ОЗУ 0x0100..0x08CF и затем байт режима (= D0 VSTAT); при смене режима (0x66C): строк = VSTAT>>3: ≥31 → 31×64, 30 → 30×64, 25..29 → 25×80, иначе 24×80; кодовая страница = VSTAT & 7 (1→страница шрифта 0x1C, 2→0x30, 3→0x44, 4→0x58, 5→0x0A, 6→0x5A, 0→0x08 [vga 0x6CC–0x70C]); VSTAT & 7 == 7 — особый режим: кодовая страница каждой строки берётся из байта экрана 0x0880+строка (& 7: 1→0x1C, 2→0x30, 3→0x44, 4→0x58, прочее → 0x08) (= Z80 0xFF80+строка, т.е. 0xF800+24×80, совпадает с «ESC G S») [код vga 0x70E–0x752]. Протокол КВУ → ВГА [код cpd 0xA00–0xA9A, vga 0x600–0x66C]: синхронный последовательный канал, **КВУ — ведущий** (программно, PORTC: PC2 — данные, PC0 — такт, PC1 — r3/r4 = 0x02/0x03 держат его в 1; приём ответа ВГА с PINC1), ВГА — ведомый на аппаратном SPI (SPCR = 0x40). Каждый байт запрашивает ВГА: кладёт байт в SPDR и даёт импульс на своём PC0 → у КВУ флаг смены уровня (PCIFR бит1, `sbis 0x1C,1` в 0xA00) → КВУ выдвигает 8 бит (старший первым) следующего байта своего буфера по указателю Y и одновременно принимает байт ВГА. Если от ВГА пришёл 0x52 — КВУ ставит Y := 0x0100 (начало кадра). Кадр со стороны ВГА: послать 0x52 (принятый в ответ байт выброшен), затем 2000 раз 0xFF → 2000 символов экрана (Y = 0x0100..0x08CF) в ОЗУ ВГА 0x0100..0x08CF, затем снова 0x52 → в ответ приходит байт по Y = 0x08D0, т.е. **VSTAT (D0)**, а указатель КВУ сбрасывается; цикл бесконечный. Курсор уже подставлен КВУ в поток (символ 0), D1/D2 в ВГА не передаются. Для ядра: «текстовый буфер 2000 байт + VSTAT + адрес курсора с битом выключения».

Начальное состояние КВУ [код cpd 0x420–0x49C]: экран заполнен пробелами, затем заставка из EEPROM КВУ (текст до 0x1F, CR = новая строка), D1 = 0x01, D0 = 0xC0 (24 строки, CP0).

## 4. Банки F4/F5 … FC/FD (пара «адрес / данные»)

Общий механизм [код IN 0x1014C–0x101B0, OUT 0x101EA–0x10250]: ЦПУ хранит последний записанный байт каждого порта F4..FF в ОЗУ AVR 0x0800+порт. Чётный порт = регистр адреса банка (чтение возвращает его). Нечётный порт: `addr = [0x0800+порт−1]`; если `addr < длина` — доступ к `база + addr`, затем `addr+1` (автоинкремент, и для IN, и для OUT); если `addr ≥ длина` — адрес не меняется, IN возвращает 0, OUT ничего не пишет.

| Адрес / данные | Длина в коде (док.) | База в ОЗУ AVR | Назначение по коду |
|---|---|---|---|
| F4 / F5 | 19 = 0x13 (док. 18) | 0x0937 | «программный ускоритель видео»: **в 4.67 никем не читается и не пишется** (поиск по 0x0937–0x0948 пуст) — просто 19 байт памяти [код] |
| F6 / F7 | 254 = 0xFE | 0x3F00 | блок системных переменных (раздел 4.1) |
| F8 / F9 | 36 = 0x24 (док. 32, «резерв») | 0x0981 | **банк CAN MCP2515** (раздел 5.3) [код] |
| FA / FB | 57 = 0x39 (док. 35) | 0x0949 | банк Ethernet (раздел «Сеть») |
| FC / FD | 134 = 0x86 | 0x36F0 | буфер прямого SPI (FE 0): +0 адрес устройства, +1 режим, +2..+133 данные |

Замечание: банки F4 и F8/FA/FC лежат в «служебной» ОЗУ AVR рядом с переменными эмулятора (0x0909…0x09AF — кольцевой буфер UART1 0x09B0); запись за пределы длины отсекается, так что Z80 не может испортить соседей.

## 5. Порт FE — команды внешних устройств

Каждая запись A в FE — команда (0x1025C); результат → ОЗУ 0x08FE, читается IN FE. Если устройство не найдено (бит HW_FOUND = 0) — 0x102A4: TCCR1B = 0, результат 0xFF.

|---|---|---|

### 5.3 CAN MCP2515 (FE 16..47, банк F8/F9)

Требует HW_FOUND бит6. SPI Y7, режим 0, 5 МГц. Номер k = FE − 16 [код 0x14A50–0x14A8A]; неизвестные k — результат = k.

### 6.1 Сопроцессор плавающей точки

0x175B2: сохраняет все регистры, свой стек 0x4080 (! за пределами 16 КБ ОЗУ 1284P — 0x4000..0x40FF; [дог.] ОЗУ 1284P = 0x0100..0x40FF, так что верно), команда c = [0x3F33]; при c < 0x10 операнды A = [0x3F34..37], B = [0x3F38..3B] (IEEE-754 single, little-endian, soft-float libgcc fp-bit). c|0x80: 0x80 → **A+B** (0x17C16), 0x81 → **A−B** (0x17BB4, меняет знак B), 0x82 → **A×B** (0x17C70), 0x83 → **A÷B** (0x17E64); иначе [0x3F33] := 0x40 (ошибка). После операции [0x3F33] = c|0x80, результат → [0x3F3C..3F] [код]. Те же операции у ловушек ED A4..A7 (FL32 0..3), которые читают операнды прямо из ОЗУ Z80 (0x176E4…) — см. cpu-core.md.

## 7. Клавиатура и консольный ввод

Состояние клавиатуры — в КВУ: D3 модификаторы, D4 скан-код, D5 символ CP866 (КВУ пишет 0x08D3/D4/D5 и ставит бит0 события, cpd 0x8F0–0x8FC). **D5 при чтении не очищается** — ЦПУ сам пишет OUT D5 ← 0 после приёма (0xE5A2, 0xE552) [код].

CONST (BIOS 2, 0xE4D0) [код]: (1) 0xEDD6 опрашивает другие источники по IOBYTE 0x3F01: бит5 TTY — кольцо UART1 → FIFO консоли (0xE884); бит6 LAN — Ethernet-команда 0x12 (FE 66); бит7 LST/RS-232 — КВУ рег. 0x21 (F1) бит7, затем 0x23 (F3) → FIFO; (2) если счётчик FIFO консоли 0x37B7 ≠ 0 → 0xFF; (3) иначе если IOBYTE бит4 и КВУ D5 ≠ 0 → 0xFF; (4) иначе 0.

CONIN (BIOS 3, 0xE4F2) [код]: 0xEDD6, затем выборка из FIFO консоли (0x37B8, 32 байта, сдвиговая очередь) — ненулевой байт отдаётся без перекодировки. Если пусто и IOBYTE бит4: читает D5; если 0 — (при 0x3F59 ≠ 0 — опрос мыши 0xFF58) и **PC Z80 −= 2**: ловушка ED выполняется заново (ожидание повторным исполнением, прерывания Z80 между повторами возможны). Есть символ: 0x3F16 := символ, 0x3F18 := D4, 0x3F17 := D3. Горячие клавиши при (D3 & 0x13) == 0x11 (Ctrl+Alt без Shift): скан 0x61 (Del) → 0x18802 (сброс/монитор, дог.); 0x05/0x06 (F1/F2) при HW_FOUND бит4 → загрузка из ПЗУ/SD (дог.); 0x77 (NumLock) → 0xFEC2 переключение режима мыши (0x3F59; КВУ DB бит6, D7 команды 0xE0/0xE1). Иначе A = символ, перевод 0x16A00, D5 ← 0; если после перевода A = 0 — снова ждать.

Перевод [код]: все платформы — 0x16DB8: повторно читает D4, таблица 0x16F3A (0x0D→0x80 TAB, 0x66→0x7F BS, 0x5A→0x9E Enter); **B = 0, C = D = код по таблице или символ, E = 0xE0, A не меняется** («CONIN возвращает данные в BC/DE» из документации). Robotron RU (0x16D80): 0x1E (NumLock = s0/s1) — щелчок 0x11310, переключение 0x0928 бит2, символ проглатывается; 0x60–0x7E → −0x20; ≥ 0x80 → таблица 0x16DFA (CP866 кириллица обоих регистров → КОИ-7 0x60–0x7E, псевдографика → пробел). Robotron EN (0x17160): ≥ 0x80 → 0 (проглатывается).

ESC k и внутренняя функция BIOS 0xF0 (0xE884) кладут байт в FIFO консоли 0x37B8 (макс. 32, иначе перенос); 0xF1 (0xE8B0) — в FIFO READER 0x3797 (счётчик 0x3796).

BDOS-ускоритель ED 27 (0x1005C) [код]: 0x3F40 := C; C=11 → CONST, A = 1 при наличии символа; C=6 → E=0xFF: CONST (+CONIN), иначе CONOUT(E); прочие — PC := 0xCABF (в настоящий BDOS).

## 8. Прерывания Z80

Механизм [код]: ISR AVR ставит бит в GPIOR0; общий хвост 0x102: GPIOR0 &= [0x3F04] (старший байт INT_MASK; незамаскированные биты **отбрасываются**); если что-то осталось — GPIOR2 := 0x2B, и следующая выборка опкода из основной таблицы уходит в 0xE012 (внутри префиксных команд DD/FD/CB/ED прерывания нет). 0xE012 возвращает GPIOR2 = 0x0A и кладёт в стек PC−1 (опкод перевыбирается).

| GPIOR0 бит | Источник | Индекс |
|---|---|---|
| 0 | PCINT3, PD7 = 1 (0xF0) | 8 |
| 2 | PCINT3, PD6 = 1 | 10 |
| 3 | PCINT3, PD0 = 1 — линия прерывания КВУ (каскад) | 0..7 |
| 6 | USART1 UDRE (0x74); UDRIE не включается — фактически не используется | 14 |
| 7 | USART1 RX (0xB6), если кольцо не переполнено | 15 |
| 1, 4, 5 | не ставятся | 9, 12, 13 |

По подписям системной консоли (индекс = порядок KBD, GPO, CTC, MUS, RS1, RS2, CTX, CRX, LAN, CAN, RTC, …) индекс 8 = LAN, 10 = RTC, 15 = TRX, 14 = TTX — т.е. **PD7 = INT ENC28J60, PD6 = INT DS1305**, индексы 0–7 = события КВУ (0 KBD, 2 CTC = таймер DE, 3 MUS, 6 CTX, 7 CRX — совпадает с битами F0) [сильная догадка: сходятся три независимых источника]. Включает ли прошивка прерывания ENC (EIE) — не проверено; FE 57 позволяет Z80 записать EIE самому.

Каскад КВУ (0xE020–0xE036): чтение КВУ рег. 0x20 (порт F0, clear-on-read) & [0x3F03] (младший байт INT_MASK) → GPIOR1; младший взведённый бит → индекс 0..7. События КВУ в F0 [код cpd]: бит0 клавиша (0x8FC), бит2 таймер DE дошёл до 0 (0x1420), бит3 мелодия закончилась (0x12E8), бит6 RS-232 передача завершена (0x1020), бит7 RS-232 принят байт (0x1012). Повторное чтение F0 затирает GPIOR1 — совмещённые события могут теряться (особенность прошивки). Подписи источников в системной консоли (0x19E22): KBD, GPO, CTC, MUS, RS1, RS2, CTX, CRX, LAN, CAN, RTC, RS3, RS4, RS5, TTX, TRX.

Что видит Z80 (0xE0E4–0xE2D4) [код]: байт источника из ОЗУ AVR 0x36CF+индекс (16 байт, настраивается в системной консоли, часть блока настроек 0x3690). Байт 0xDD — как NMI: push PC, IFF2 := IFF1, IFF1 := 0, PC := 0x0066 (без учёта IFF1). Иначе при IFF1 = 0 запрос **сбрасывается**. Иначе push PC, IFF1/IFF2 → 0x09A9/0x09AA, IFF := 0, затем по IM (0x090B): IM 2 — PC := слово по адресу (I<<8)\|байт (I = 0x0900); IM 1 — PC := 0x0038; IM 0 — байт исполняется как опкод через страницу 0x0A (PC уже положен в стек — для RST будет двойной push, ошибка прошивки).

Разводка: PD0 ← КВУ PD6 [дог.], PD7 ← ENC28J60 INT, PD6 ← DS1305 INT (см. выше).

## 11. Сеть (ENC28J60): FE 48..79, банк FA/FB, UDP-каналы

**Итог для эмуляции через ESP8266 (AT-команды, только сокеты TCP/UDP).** Почти весь API оперирует готовыми кадрами Ethernet: пакеты собирает AVR в своём ОЗУ, команды 54/55 отправляют/принимают кадр целиком. Через UDP-сокет естественно эмулируются: 61/69 (собрать/отправить UDP), 67 (прочитать данные UDP), 66 с кодом 0x83, вывод CON/LST/PUNCH в сеть (1 символ = 1 датаграмма), ввод CON/READER из сети (0x84/0x85). Для команд 54/55 придётся разбирать собранный кадр (60/61/63) и синтезировать принятый (заголовки Ethernet+IP+UDP). Сырые команды — заглушки: 52/53/57/58/65/56 (регистры ENC/PHY; 56 EPKTCNT и 65 ESTAT можно подделать), 62/68/70/71 (ARP/ICMP; на входящий ping ESP отвечает сама), 72 (TCP — своя сборка сегментов; и так испорчена, см. ниже). Всё ниже — [код], если не помечено.

### 11.1 Общие правила

- Вход: OUT FE, A = 48..79 → 0x12800, r21 = A − 48 (0x10298). Работает, если HW_FOUND бит5 (FLAN) = 1 **и** бит5 байта 0x36C0 (настройка «DISABLE: R LAN») = 0; иначе 0x102A4 → результат 0xFF.
- Результат → 0x08FE (0x1290C), IN FE. У многих команд результат — мусор (последний r21: байт SPI или длины) — помечено «мусор».
- Диспетчер, группа без SPI (возврат 0x1290C): индексы 2, 3, 0B–0F, 10, 13–18; группа с SPI (возврат 0x12906, выключает SPI): 0, 1, 4–9, 0A, 11, 12. Индексы 0x19..0x1F (FE 73..79) → 0xFD. Внутренние r21 = 0x77..0x7A только из BIOS.
- ENC28J60: PORTB = 0x19 (Y1, логическое устройство 9), SPCR = 0x50, SPSR = 1 → 10 МГц.
- Внутренний буфер кадра: ОЗУ AVR 0x3200, максимум 0x300 = 768 байт. Указатель 0x3658/59, длина 0x365A/5B, предел 0x365C/5D; рабочие копии: MAC назн. 0x364C, IP назн. 0x3652, порт назн. 0x3656, порт ист. 0x364A, протокол 0x365E. «Setup» 0x1352C: длина = LAN_MBUF_OUT_L, указатель = 0x3200, предел 0x300, копии из банка.

### 11.4 Инициализация ENC28J60 (0x12BFA)

Soft reset (SRC) + 5 пауз; ERXST = 0x0000, ERXND = 0x19FF, ERXRDPT = 0, RXDPT банка = 0; ETXST = 0x1A00 (ставится при каждой отправке). MACON1 = 0x0D, MACON3 = 0x33 (дополнение+CRC, проверка длины, полный дуплекс), MACON4 = 0x40, MAMXFL = 0x05DC, MABBIPG = 0x15, MAIPGL = 0x12. MAADR = 43:E8:9F:B3:5F:BC (0x12CF4–0x12D4C; бит0 первого байта = групповой адрес — вероятно, ошибка автора). PHCON2 = 0x0100, PHCON1 = 0x0100, PHLCON = 0x3472. BFS ECON1.RXEN. ERXFCON не пишется (по умолчанию 0xA1) [дог.]. Отправка 0x137F6: ждать сброса TXRTS (≤ 200 попыток), TXRST вкл/выкл, очистить EIR, ETXST = 0x1A00, WBM: управляющий байт 0 + данные, ETXND = 0x1A00 + len, TXRTS. При загрузке (0x11798): банк 3, RCR EREVID, 0xFF = нет чипа; найден → HW_FOUND бит5, затем init командой 49 (если найдены часы, HW_FOUND бит3) или 48.

### 11.6 Команда 66 — «фоновая» обработка (0x13726)

Фоновой обработки на стороне AVR нет (ни прерывания, ни опроса в цикле): автоответы ARP/ping работают **только** когда Z80 вызывает FE 66 или BIOS опрашивает CON/READER с битом LAN. Если MAIN_RQST ≠ 0 → сразу 0xFE. Иначе, пока EPKTCNT ≠ 0: принять кадр в 0x3600 (**≤ 64 байта**), классифицировать; 0x81 → ARP-ответ и отправка; 0x8A → перечитать кадр (≤ 256 байт в 0x3500), echo reply, отправка (автоответ на ping); 0x83/0x86 → MAIN_RQST = код, шаг команды 55 (кадр целиком в 0x3200, MBUF_IN_L), выход (рез. мусор — Z80 смотрит MAIN_RQST); 0x84 при PR_IOBYTE (0x3F48) бит6 → данные (len − 42, кадр урезан до 64 → **≤ 22 байт**) в FIFO READER (0xE8B0: 0x3797, 32 байта, счётчик 0x3796); 0x85 при CON_IOBYTE (0x3F01) бит6 → в FIFO консоли (0xE884: 0x37B8, 32 байта, счётчик 0x37B7); байты 0x00 отбрасываются; при переполнении FIFO — выход **без освобождения пакета** (при следующем вызове байты повторятся); прочие кадры освобождаются.

Биты IOBYTE: бит2 = вывод LAN, бит6 = ввод LAN.

## 12. Консольный вывод (CONOUT) и ESC-интерпретатор

### 12.1 Вход и маршрутизация

BIOS 4 = **0xE5B4 CONOUT** (символ в C = r22). Разветвление по CON_IOBYTE 0x3F01: бит1 → TTY/UART1 (0xEC90 → 0x11298), бит2 → LAN (0xECEC, раздел 11.7), бит3 → LST (0x114D4), бит0 → экран [код].

Экранный путь [код]:
- 0x091C ≠ 0 (идёт сбор ESC) → 0xEB3E; иначе символ < 0x20: 0x1B начинает ESC (0xE63A), прочие → `jmp 0x16A04` (таблица управляющих кодов платформы); символ ≥ 0x20 → `call 0x16A02` (перекодировка платформы; результат 0 — ничего не печатать).
- Печать 0xE600: (если CRT_SETTINGS бит6 — поправка теневых атрибутов 0xF1EE) → 0xE81E: запись символа в ОЗУ Z80 по адресу VIDEO_CURSOR + 0xF700 (с зеркалом в КВУ) → если старый X ≥ CHARS — CR+LF (0xEDF0), иначе VIDEO_CURSOR+1 → 0xEA3A (пересчёт X/Y, отправка D1/D2).
- Сборщик ESC 0xEB3E: n-й байт после ESC → 0x091C+n (первый параметр 0x091D), r18 = длина с ESC; обработчик платформы 0x16A06 возвращает новый r18 (0 = готово); > 8 байт — сброс. **Неизвестная ESC x в режиме CRISS «съедает» ещё 5 байт** (обработчик 0x16BFE сбрасывает только на длине 6).

Платформы — таблица раздела 3; параметры по умолчанию из записей 0x16A10: все 24×80; CRT_SETTINGS 0x00 / 0x42 / 0x43 / 0x03 / 0x03 / 0x00 / 0x43. Перекодировка печатных: CRISS, Kaypro 8bit, VT — только 0xFF → 0x7F (0x7F и 0x80–0xFE печатаются как есть); Kaypro — & 0x7F, инверсия → |0x80; TRS-80 — & 0x7F; Robotron — 12.3.

### 12.2 Экран

- **Экран — это ОЗУ Z80 F800 + (y−1)·CHARS + (x−1)**, линейно, шаг CHARS (80 или 64). Конец: 24×80 → FF80, 25×80 → FFD0, 30×64 → FF80, 31×64 → FFC0 [код].
- Любая запись Z80 (программы, BIOS, INIR, LDIR…) по адресу ≥ F800 дублируется в КВУ (раздел 2.2). Прокрутка, вставка/удаление строк, очистка — ЦПУ побайтно (чтение ОЗУ Z80 + запись с зеркалом); аппаратной прокрутки нет [код].
- Курсор: после каждого символа 0xEA76 пишет D1 = CURSOR_STATUS \| VIDEO_CURSOR.hi, D2 = VIDEO_CURSOR.lo (2 записи SPI). VSTAT (D0) = LINES<<3 \| CP пишется только в 0xEC2C и ESC G s/w [код].
- 0xEC2C (применить режим): VSTAT → D0; CURSOR_STATUS = 0x80 при CP = 1 (графика), иначе 0; VIDEO_END = LINES·CHARS + 0x100; сброс строки статуса и верхней границы прокрутки; окно выключено; команда CLR 0 [код].
- Заполнение при очистке: 0x00 при CP = 1, иначе 0x20.
- Перенос: печать в последнем столбце сразу делает CR+LF, поэтому символ в правом нижнем углу сразу прокручивает экран (при ^N — курсор в столбец 1 последней строки) [код].
- Переход 24 → 25 строк не чистит строку 25 (очистка по старому VIDEO_END) [код].
- Теневая память атрибутов: ОЗУ AVR 0x0100–0x08CF, только для 24×80, кодирование серий (ячейка с битом7 начинает серию, значение действует до следующего маркера); биты Robotron 0x10 инверсия, 0x04 s1 [код]. **Тот же буфер используется ESC B S / ESC C S** (сохранение экрана) — они портят атрибуты.

### 12.5 Псевдографика 160×96 (0xF612)

- Ячейка 2×4 точки в **CP1**: код символа = маска точек; адрес = F800 + (y>>2)·CHARS + (x>>1); бит = 2·(y & 3) + (x & 1): бит0 — верх-лево, бит1 — верх-право, … бит7 — низ-право [код].
- y, x — сырые, с 0; принимаются y ≤ 0x60, x ≤ 0xA0 (строка 24 и столбец 80 тоже «допустимы» — граница на 1 больше); вне — точка пропускается. Поставить = OR, стереть = AND NOT, инвертировать = XOR.
- Линия (0xF734): n = max(\|dy\|, \|dx\|), рисуется n+1 точка; накопители ошибок прибавляют \|dy\| и \|dx\| за шаг, при достижении n — вычесть n и шагнуть по оси.
- Окружность (0xF846), всегда OR: a = 0, b = R, d = 3 − 2R; пока a < b: точки; если d < 0 — d += 4a + 6, иначе d += 4(a − b) + 6 (у классики +10) и b−−; a++. В конце одна точка, только если b = 0. S — маска октантов (dy, dx от центра): бит0 (+b, +a), 1 (−b, +a), 2 (+b, −a), 3 (−b, −a), 4 (+a, +b), 5 (−a, +b), 6 (+a, −b), 7 (−a, −b); S = 0xFF — полная окружность.

### 12.6 Цвет: модуль CLR (0x16800; r21 = команда, r22 = аргумент)

Требует HW_FOUND бит1; ESC q/r/s также требуют LINES = 24 (иначе 0x08FE = 0xFF); команды 2–7 — ещё и CRT_SETTINGS бит4 (ставится ESC r P). SPI: PORTB = 0x17 (PB3 = 0 — дешифратор выключен), PD1 и PB4 низкие; квитирование: ждать MISO (PB6) = 0 (готов), послать байт, ждать MISO = 1; тайм-аут ≈ 1,05 с → 0x08FE = 0xFF; ответ 0 — повтор байта; ответ → 0x08FE [код]. Как CLR физически подключён к SPI при выключенном дешифраторе — открытый вопрос.

| Команда | Байт | Откуда |
|---|---|---|
| 0 | 0x00 | 0xEC2C (сбрасывает CRT_SETTINGS бит4); ESC r с неизвестной буквой |
| 1 цвет c | 0x01 + c | ESC r H R G Y B M C W = 0..7 |
| 2 серия | 0x80 \| ((n−1)<<3) \| c | ESC s |
| 3 столбец x (0–79) | 0x11 + x | ESC s |
| 4 строка y (0–23) | 0x61 + y | ESC s |
| 5 | 0x79 | недостижима |
| 6 очистка | 0x7A | ESC r E, CLS |
| 7 прокрутка | 0x7B | ESC r S, LF внизу |
| 8 | 0x7F | ESC r P (ставит CRT_SETTINGS бит4) |
| FF | c как есть | ESC q c |

ESC s n c (0xFD3C): столбец (X−1), строка (Y−1), затем байт серии при n ≤ 16; при n > 16 — 0x78 \| c, сдвиг на 16 столбцов и повтор, до столбца 80; n = 0 — только позиция. Тени атрибутов и курсор не трогает [код]. Для ядра: CLR = атрибутная память 80×24 по 3 бита цвета, команды выше — её интерфейс; HW_FOUND бит1 = 1.

### 12.7 Прочие

- **ESC m** (0xFC5E): каждый байт → КВУ рег. 0x10 + k (порты E0, E1, …), до 16 байт; байт 0x04 завершает ноты, следующий байт → D6 (команда) и конец. Лишние ноты > 16 игнорируются до 0x04. Формат: ESC m n1..nk 04 cmd [код].
- **ESC g ch v** (0xF8D0 → 0xED6C; ошибка 4.67): пишет D8 = v, затем D7 = байт, который КВУ выдвинул во время передачи (вероятно 0x48), **ch не используется**; затем опрос D7 до значения < 2 [код]. Для ядра: реализовать задуманное (D8 = v, D7 = ch).
- **BELL** (0x11310): см. 2.1 — Y3 ≈ 197 мс (таймер 1, /1024, OCR1A = 0x0F00) [код; длительность пересчитана по регистрам].
- Расширенные функции BIOS 0xF9–0xFC (атрибуты Robotron: 0xF2AE, 0xF1C0, 0xF246) — см. cpu-core.md.

## 14. Риски для ядра и открытые вопросы

Риски:
1. Экран = ОЗУ Z80 F800–FFFF (а не отдельная видеопамять): программы читают и пишут его напрямую; видеоадаптер ядра должен «подсматривать» записи Z80 в F800–FFCF (линейно, шаг 80 или 64), как КВУ. Байты FFD0–FFFF на экран не попадают; FF80+строка в режиме CP7 — список кодовых страниц.
2. Курсор: адрес с базой 0x100 и бит7 «выключен» в D1; мигание и подмена на символ 0 — на стороне КВУ.
3. Порты D0–F3 — регистры КВУ: в ядре нужен эквивалент КВУ (клавиатура, таймер DE, мелодии, RS-232, мышь, SYSRQ, событийный регистр F0 для прерываний).
4. Ошибки прошивки, которые программы могут «использовать»: ESC Z берёт CHARS из A; FF 39 шлёт не тот байт; ESC g не использует ch; VT52 ESC B = CR; ESC B4/C4 наоборот относительно документации; неизвестная ESC съедает 5 байт. Решение — повторять поведение 4.67, кроме явно сломанных (FF 39, ESC g), и записать это в PLAN.md.
5. Сеть: API на уровне кадров Ethernet; через ESP8266 честно реализуется только UDP-подмножество (раздел 11).
6. Настройки (IP/MAC, флаги запрета, векторы прерываний) — 96 байт NVRAM DS1305 по адресам ОЗУ AVR 0x3690..0x36EF; их надо где-то хранить (файл на SD).

Открытые вопросы:
1. Протокол КВУ → ВГА разобран (2.3); не разобрано, на какой вывод КВУ приходит импульс PC0 ВГА (PCINT1 КВУ, бит маски не смотрел) — для ядра не нужно.
2. Как модуль CLR подключён к SPI при PORTB = 0x17 (дешифратор выключен) — схема 6.12 (Радио № 12/2023).
3. PD6/PD7 = DS1305/ENC28J60 — по подписям консоли; по схеме не сверено.
4. Назначение 19 байт банка F4/F5 (в 4.67 не используются) и битов HW_FOUND 2.
5. Байты CRT_SETTINGS платформ (0x42/0x43): бит6 — тени атрибутов (подтверждено для 24×80), что значит бит1 у 0x42/0x43 вне CP.
6. FE 2–15 при наличии ПЗУ — пустые (возможно, команды EEPROM вырезаны в 4.67).
7. VT100: остальные ветки CSI/VT52 (кроме H/f) не перепроверялись.
8. Где ERXFCON ENC28J60 (по умолчанию 0xA1) и подключён ли INT ENC.

### 12.8 Подробности для Ф2

Всё ниже — [код], перепроверено по `cpu467.S` (адреса указаны). Обозначения: X, Y = CURSOR_X/Y (0x3F06/07, с 1, **физическая** строка экрана), LINES/CHARS = 0x3F09/0A, VEND = 0x3F0B/0C, «верх прокрутки» TOP = 0x3F6C/6D (смещение с базой 0x100, старт 0x0100), STAT = 0x3F6E.

**Позиционирование.** Смещение курсора всегда считается абсолютно: VIDEO_CURSOR = 0x100 + (Y−1)·CHARS + (X−1) (0xE9FA), обратный пересчёт 0xEA3A. Общая подпрограмма 0xF338 (вход: r21 = строка, r22 = столбец, с 1): строка > LINES — игнор всей команды; если STAT = 1 (строка статуса сверху) — строка + 1; столбец > CHARS — игнор; нижние границы не проверяются (0 даёт ячейку левее / строку выше). Через 0xF338 идут: ESC = (−31), ESC Y (+1), ESC (y+127)(x+127) (−127), ESC y (окно), 8275 OUT 18h — нет (пишет X/Y напрямую). ESC 0x09 x — только столбец (0xF316, x ≤ CHARS).

#### 1. Окно (ESC W / w / y; 0x3F66..0x3F6B)

- **Обычный вывод окно не учитывает.** Переменные окна читаются только в 0xF98A–0xFC5A (ESC W, w, y); печать (0xE600), CR, LF, BS, TAB, CLS, HOME, ESC =, ESC Y, очистки, прокрутка их не используют [поиск обращений к 0x3F66..0x3F6B: 0xEC80, 0xF9A0–0xFC50]. Окно — только «рамка/очистка/прокрутка прямоугольника» плюс относительное позиционирование ESC y; дальше текст печатается обычным образом (с переносом на всю ширину экрана).
- ESC W x1 y1 x2 y2 (0xF98A): 1 ≤ x1 ≤ CHARS, 1 ≤ y1 ≤ LINES, x1 ≤ x2 ≤ CHARS, y1 ≤ y2 ≤ LINES; при ошибке все четыре := 0 (окно выключено). 0x3F6A = 0x3F6B := 1. Курсор не двигается.
- Окно выключается (0x3F66 := 0): неверный ESC W (0xFA0C); 0xEC2C (ESC Z, ESC G 0–9/S, OUT 19h/18h — смена числа строк Robotron); ESC G N (0xF60C). CLS окно **не** выключает. Признак «окно есть» — 0x3F66 ≠ 0.
- База окна (0xFABE): адрес Z80 = F800 + (y1−1)·CHARS + (x1−1); ширина w = x2−x1+1 (0xFB4E), высота h = y2−y1+1 (0xFB60). Без окна ESC w и ESC y игнорируются.
- ESC w C (0xFB72): все ячейки окна := 0x20 (в любом режиме, и в CP1).
- ESC w U (0xFBE6): строки окна 2..h копируются на одну вверх (ширина w, побайтно через ОЗУ Z80 с зеркалом), строка h := 0x20.
- ESC w F / f (0xFB8C / 0xFB92): рамка рисуется **на граничных ячейках самого окна**: строка 1 = угол, (w−2) × горизонталь, угол; строки 2..h−1 = вертикаль, (w−2) × **0x20**, вертикаль — т.е. рамка заодно очищает внутренность; строка h = угол, горизонталь, угол. h = 1 — только верхняя строка, h = 2 — верх и низ. Символы: F = C9 CD BB / BA 20 BA / C8 CD BC (0x11F4A), f = DA C4 BF / B3 20 B3 / C0 C4 D9 (0x11F54). Ошибка: при w = 1 счётчик w−2 = 0xFF → пишется 255 горизонталей подряд (за окно).
- Все ESC w: курсор, D1/D2, атрибуты, CLR не трогаются.
- ESC y r c (0xFC12): 1 ≤ r ≤ h, 1 ≤ c ≤ w, иначе игнор; 0x3F6B := r, 0x3F6A := c; затем 0xF338(y1+r−1, x1+c−1) — т.е. и тут действует сдвиг +1 при строке статуса сверху. 0x3F6A/6B больше нигде не читаются.

#### 2. Строка статуса (ESC a T / a B; STAT = 0x3F6E)

| Что | ESC a T (STAT = 1) | ESC a B (STAT = старый LINES) |
|---|---|---|
| Установка (0xFE52) | только при STAT = 0: LINES −= 1, TOP += CHARS | только при STAT = 0: STAT = LINES, LINES −= 1, VEND −= CHARS |
| Прокрутка LF (0xEDFC → 0xE8F8) | диапазон TOP..VEND = физ. строки 2..LINES+1; LF при Y ≥ LINES (= 23) прокручивает, Y остаётся 23 → **физ. строка 24 после прокрутки всегда пустая** (ошибка) | диапазон строки 1..LINES; строка статуса вне диапазона |
| CLS (0C, ESC j: 0xEB26 → 0xEAA6, заполнение TOP..VEND) | строка статуса **не** очищается | не очищается |
| ^T / ESC J (0xEEA2) | от курсора до VEND (строку статуса не задевает, если курсор ниже) | до нового VEND — не задевает |
| HOME (01, ESC H, конец CLS: 0xEE5C) | X = Y = 1 → **курсор на строке статуса** (сдвига нет) | строка 1 — нормально |
| ESC =, ESC Y, ESC (y+127), ESC y | строка ≤ LINES, затем +1 → физ. 2..24 | строка ≤ LINES, без сдвига |
| Снятие | только 0xEC2C (смена режима) или ESC G N; повторный ESC a игнорируется | то же |

ESC A x (0xFE40): сохранить X, Y, CURSOR_STATUS в 0x0925/26/27 (те же ячейки, что ESC B 6), CURSOR_STATUS := 0x80 (курсор скрыт), затем 0xF354: Y := STAT, X := x при x ≤ CHARS (иначе только сохранение и скрытие; x = 0 принимается). Без строки статуса STAT = 0 → Y = 0 → курсор на F800 − CHARS (ОЗУ Z80 ниже экрана, без зеркала; ошибка). Дальше символы печатаются в строку статуса обычной печатью; перенос в конце строки: для B (Y = STAT > LINES) — CR+LF → прокрутка текстовой области, Y остаётся на строке статуса; для T — Y = 2 (уход в текст). **Возврат — ESC C 6** (0xF2FC: X, Y, CURSOR_STATUS из 0x0925–0x0927, затем 0xEA34 — пересчёт и D1/D2). Отдельной команды «выйти из строки статуса» нет.

#### 3. ESC B S / ESC C S

- B S (0xF8DE): Z80 F800..FFCF (ровно 2000 байт, независимо от режима и LINES) → ОЗУ AVR 0x0100..0x08CF. Курсор не сохраняется.
- C S (0xF914): обратно, каждый байт записью в ОЗУ Z80 **с зеркалом в КВУ** (2000 кадров SPI). X/Y/CURSOR_STATUS/D1/D2 не меняются, CLR не уведомляется. Буфер общий с тенью атрибутов Robotron (CRT_SETTINGS бит6).

#### 4. ESC | c (0xFDB8)

Читает старый байт ОЗУ Z80 по курсору (VIDEO_CURSOR + 0xF700), пишет c **с зеркалом** (КВУ, т.е. экран, показывает c), затем пишет старый байт обратно в ОЗУ Z80 **без зеркала** (0xFE2C–0xFE38). Итог: на экране c, в ОЗУ Z80 прежний байт, курсор не движется, D1/D2 не пишутся. Для ядра с «подсматриванием» записей Z80 нужен отдельный путь «записать только в видеобуфер».

#### 5. Псевдографика

- Режим **не проверяется**: в любом режиме команды меняют биты кода символа в ячейке F800 + (y>>2)·CHARS + (x>>1) (0xF612; шаг CHARS, т.е. и в 64-колоночных режимах). Видно как точки только при CP1 (ESC G 4).
- Параметры — сырые байты, с 0, **сначала y**: ESC * y x, ESC SP y x, ESC # y x (y = 0x091E, x = последний байт); y ≤ 0x60, x ≤ 0xA0 (на 1 больше экрана), иначе точка пропускается.
- ESC L / D / x y1 x1 y2 x2 (0xF734: y1 = 0x091E, x1 = 0x091F, y2 = 0x0920, x2 = 0x0921).
- ESC c S y x R (0xF846: S = 0x091E, y = 0x091F, x = 0x0920, R = 0x0921); координаты точек — 8-битные суммы центр ± смещение (отрицательные → большие → пропуск).
- Запись каждой точки — чтение-изменение-запись ОЗУ Z80 с зеркалом (0xF66C: только при адресе ≥ F800). Курсор не двигается.

#### 6. CLR: модель «событие ЦПУ → байт»

Отправка — 0x16800 (r21 = команда, r22 = аргумент); всё — только при HW_FOUND бит1. Байт уходит с квитированием (раздел 12.6); ответ CLR 0 → повтор того же байта; тайм-аут 1,05 с (таймер 1, OCR1A = 0x5000) → 0x08FE = 0xFF. Обёртка 0xFC96 у ESC q/r/s и у уведомлений CLS/прокрутки: **если LINES ≠ 24 — ничего не посылается** (в т.ч. при строке статуса, когда LINES = 23).

Флаг CRT_SETTINGS бит4 («режим цветовых схем») держит ЦПУ: ставит команда 8 (0x7F), **сбрасывают команды 0 и 1** (0x168E0: и цвет ESC r H..W тоже выводит из режима схем). Команды 2–7 посылаются только при бит4 = 1, иначе 0x08FE = 0xFF и ничего не уходит.

| Событие ЦПУ | Условие | Байт(ы) |
|---|---|---|
| 0xEC2C — любая смена режима (ESC Z, ESC G 0–9/S, ESC G N, OUT 19h/18h Robotron, старт) | HW_FOUND бит1 (LINES не проверяется) | 0x00; бит4 := 0 |
| ESC r H/R/G/Y/B/M/C/W | LINES = 24 | 0x01 + c (c = 0..7 в этом порядке: чёрный, красный, зелёный, жёлтый, синий, малиновый, циан, белый); бит4 := 0 |
| ESC r P | LINES = 24 | 0x7F; бит4 := 1 |
| ESC r E | LINES = 24, бит4 | 0x7A |
| ESC r S | LINES = 24, бит4 | 0x7B |
| ESC r L | — | в CLR ничего; очистка текстового экрана + HOME |
| ESC r другая буква | LINES = 24 | 0x00; бит4 := 0 |
| ESC q c | LINES = 24 | c как есть (бит4 не меняется) |
| CLS (0C, ESC j; 0xEE4A → 0xFCC4) | LINES = 24, бит4 | 0x7A |
| LF с прокруткой (0xEE1A → 0xFCBA) | LINES = 24, бит4 | 0x7B (на каждую прокрутку) |
| ESC s n c (0xFD3C) | LINES = 24, бит4 | столбец: 0x11 + (X−1+k) при < 80 (иначе стоп); пауза; строка: 0x61 + (Y−1) (при Y−1 < 24); пауза; n = 0 — всё; n ≤ 16 — 0x80 \| ((n−1)<<3) \| (c & 7) и конец; n > 16 — 0xF8 \| c (серия 16), n −= 16, k += 16, повтор с новой позиции |

Не уведомляют CLR: печать символов, ESC R/E (удалить/вставить строку), ^T/^V/^X/ESC J/K, ESC w (окно), ESC B/C S, прокрутка при запрещённом ^N (её нет), ESC G s/w. Курсор ЦПУ не двигает (ESC s позиционирует только CLR). Что CLR делает с цветом при бит4 = 0 (вне режима схем: 0x01 + c — общий цвет вывода?) и как он узнаёт позицию печатаемых символов — в прошивке CLR (`clr.S`), не в ЦПУ.

#### 7. CURSOR_STATUS (0x3F08) и D1/D2

Значения только 0x00 (виден) и 0x80 (скрыт); D1 = CURSOR_STATUS \| VIDEO_CURSOR.hi пишется в 0xEA76 после каждого перемещения. Все записи 0x3F08 [поиск `sts 0x3F08`]:

| Где | Значение | Кто |
|---|---|---|
| 0xEC52 | 0x80 при CP = 1, иначе 0 | 0xEC2C — любая смена режима (так ESC G 4 скрывает курсор, а ESC G 0 и др. — показывают) |
| 0xF148 | 0x80 | ESC 0, 0x1E, ESC C 4, Robotron 0x83 |
| 0xF150 | 0 | ESC 1, 0x1F, ESC B 4, Robotron 0x82 |
| 0xFE46 | 0x80 | ESC A x |
| 0xF310 | сохранённое | ESC C 6 |
| 0xF19E, 0xF600 | 0 | сброс платформы 0xF156 / ESC G N (затем 0xEC2C) |
| 0x1108E | 0 | старт |

Окно и строка статуса (кроме ESC A) курсор не скрывают.

#### 8. ESC CRISS — полная таблица разбора (0x16BFE)

Длина считается с ESC; по достижении длины проверяется ESC1 = 0x091D:

| Длина | Команды |
|---|---|
| 2 | `0` `1` `j` `H` `J` `K` `R` `E` |
| 3 | `A` `a` `B` `C` 0x09 `^` `_` `Z` `G` `\` `\|` `k` `w` `m` (дальше переменная длина, 0xFC5E) `q` `r`; любой ESC1 ≥ 0x80 (ESC (y+127)(x+127)) |
| 4 | `=` `Y` `y` `*` SP `#` `S` (ничего) `g` `s` |
| 5 | — (неизвестные продолжают сбор) |
| 6 | `c` `L` `D` `x` `W`; неизвестная — конец, отбрасывается |

Других последовательностей в обработчике CRISS нет; таблица 12.4 полная. ESC G с неизвестным m (кроме 0–9, S, N, s, w) ничего не делает (0xF5EE). ESC Z / ESC G 0–9/S: LINES, CHARS, CRT_SETTINGS := v & 7 (биты 4, 6, 7 сброшены), HOME, CLS по **старому** VEND и TOP, затем 0xEC2C (D0, курсор, VEND, TOP := 0x0100, STAT := 0, окно выкл, CLR 0x00). ESC G N (0xF5F4): заполнение 0x20 от TOP до VEND, курсор вкл, HOME, окно выкл, затем 0xF156: LINES/CHARS/CRT_SETTINGS платформы из 0x16A10, 0x091C/0x0928/0x0929 := 0, 0xEC2C, очистка теней (0xF1A4).
