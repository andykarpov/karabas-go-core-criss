## 0. Главное для ядра (кратко)

1. **Все три МК (ЦПУ, КВУ, ВГА) работают на 20 МГц**, не 8 МГц: КВУ — UBRR0=129 → 9600 бод только при 20 МГц, таблица тонов даёт 880,0 Гц для индекса 1 только при 20 МГц, таймер 0 CTC /1024 OCR0A=195 → 10,03 мс [код cpd 0x4C0, 0x4D2–0x4DC, 0x4400]. ВГА: 19 тактов на 3 символа = 6,333 такта/символ при 20 МГц ≈ 8 точек при 25,175 МГц [код vga 0xB6…]. На схеме 3.x кварц ZQ2 20 МГц стоит у КВУ (DD5), XTAL1 ЦПУ и ВГА — от общей цепи [схема, дог. что это выход генератора DD5].
2. **Видео = стандарт VGA 640×480@60**: точка 25,175 МГц, 800×525, строчный 96 т. (отр.), передняя площадка 16, задняя 48; кадровый 2 строки (отр.), передняя 10, задняя 33 [код ATtiny13]. Поле 640 точек = 80 знакомест по 8 точек.
3. **Экран (2000 байт) живёт в КВУ**, ЦПУ пишет в него трёхбайтовыми кадрами; КВУ непрерывно «прокачивает» экран + байт режима в ВГА, подставляя на место курсора код 0 (мигание 0,5 с / 0,5 с). Своего буфера у ВГА 2000 байт — это копия.
4. Знакоместо всегда 8 точек шириной; высота 20 / 19 / 16 / 15 строк растра для 24 / 25 / 30 / 31 строк текста. Шрифт хранится «по строкам растра»: строка r всех 256 символов — одна страница 256 байт.
5. **В режимах 64 столбца на экран выводится только 61 знакоместо** (столбцы 0..60, поле 488 точек слева, справа чёрное), шаг строки в буфере — 64 [код vga 0x2F6–0x48E: 61 команда `out`].
6. Псевдографика 160×96 — это просто CP1 (или старый CP4): символ = блок 2×4 «точки», бит 2k — левая, 2k+1 — правая точка в k-й четверти высоты; точка 4×5 растра (горит 3×4).
7. «Композитный режим» в истории прошивок ВГА — **не композитный видеовыход**, а «составной» режим 7: своя кодовая страница для каждой строки текста (таблица в буфере экрана, смещение 1920). Аналогового композита в прошивках нет.
8. CLR (ATtiny84, 20 МГц) хранит **цвет переднего плана по знакоместам** в виде RLE (20 байт на строку текста, 24 строки), 8 цветов RGB по 1 биту; работает только для геометрии 24×80×20; есть режим «весь экран одним цветом» (по умолчанию зелёный, EEPROM 0x1FF = 2).

## 1. Схема соединений (по схеме 3.x) [схема]

| Цепь | Откуда → куда | Назначение |
|---|---|---|
| SPI ЦПУ (MOSI/MISO/SCK) | DD1 (1284P) → DD5 КВУ PB3/PB4/PB5 | ЦПУ — мастер, КВУ — ведомый (аппаратный SPI, прерывание) |
| PC3/PC2/PC1/PC0 КВУ | → PB2 (SS) / PB3 (MOSI) / PB4 (MISO) / PB5 (SCK) ВГА DD8 | программный SPI-мастер КВУ → аппаратный ведомый ВГА [код cpd 0xA06–0xA90] |
| PC0 ВГА | → PD3 (INT1) КВУ | «дай байт»: ВГА опускает PC0 на 5 тактов (250 нс: `cbi`, 3×`nop`, `sbi`) перед каждым байтом [код vga 0x60A–0x612] |
| PB1 ВГА | → КТ3 «ERR» | 1 во время приёма байта режима (контрольная точка) [код vga 0x63E/0x656] |
| PORTD ВГА PD0..PD7 | → 74HC166 D0..D7 (DD9) | байт строки знака; Q7 = видеосигнал (первой выходит D7 = PD7 = бит7) |
| G2 25,175 МГц | → CP 74HC166, CP 74HC393 (DD10.2) | точечная частота (через S1 «ACLK» можно взять 25 МГц с CLKOUT ENC28J60) |
| 74HC393 Q1 (12,5875 МГц) | → CLKI ATtiny13 (DD11), через DD3.2 (инвертор) на DD3.3 | такт ГСС = точка/2 |
| ATtiny13 PB4 | → DD3.3; выход DD3.3 → /PE 74HC166 | /PE = NAND(не Q1, PB4): загрузка сдвигового регистра раз в 8 точек |
| ATtiny13 PB2 | → /MR 74HC166 | гашение (0 = регистр сброшен, чёрное) |
| ATtiny13 PB0 / PB1 | → HSYNC / VSYNC разъёма (через 51 Ом) и на ВГА PB0 (PCINT0) / PC3 (PCINT11) | синхроимпульсы генерирует ATtiny13 |
| ВГА PC2 | → /RESET ATtiny13 | сон: ВГА держит ATtiny13 в сбросе → нет синхроимпульсов [код vga 0x670–0x672] |
| КВУ PD2 / PD4 | KB CLK / KB DATA (XP7) | клавиатура PS/2 (INT0) |
| КВУ PC4 / PC5 | SDA / SCL (XP7) | I2C (TWI) **или** мышь PS/2 программно (данные PC4, такт PC5) |
| КВУ PD0 / PD1 | MAX232 (DD7) | RS-232 (USART0) |
| КВУ PB1 (OC1A) | → TDA7052 | синтезатор мелодий (переключение OC1A) |
| КВУ PD6 | → ЦПУ (линия прерывания, см. cpu-io.md §8) | импульс «есть событие» [код cpd 0x183A–0x1846] |
| КВУ PD7 | → сброс | импульс сброса [код cpd 0x1816–0x1824] |

Версия 6.x (цвет): добавлены ATtiny84 (CLR) и 74HC173 (74LS295 в 6.09) [док. color6.txt]. Разводка CLR по коду: PB1 = HSYNC (PCINT9), PA7 = VSYNC (PCINT7), PB2 = INT0 = выборка от ЦПУ (спад), PA4/PA6/PA5 = USCK/DI/DO (USI, трёхпроводный), PA0..PA2 = цвет → 74HC173, PA3 = выход «режима» [код clr 0x6E8–0x73A]; куда подключены выходы 74HC173 и чем тактируется — [дог.] тем же сигналом загрузки, что и 74HC166 (выдача цвета идёт тем же темпом 19 тактов/3 знака).

## 2. Видеоконтроллер

### 2.1 ГСС ATtiny13 (DD11 в 3.x, DD12 в 6.x; файлы `criss0/DD11.hex` = `criss1/DD12.hex`, 0x000–0x33F) [код]

Такт 12,5875 МГц (1 такт = 2 точки). PORTB: PB0 = HSYNC, PB1 = VSYNC, PB2 = /MR (гашение), PB4 = разрешение загрузки; DDRB = 0x17. Константы в регистрах: r4 = 0x17 (всё + загрузка), r5 = 0x07 (без загрузки), r7 = 0x03 (гашение, HS=1, VS=1), r8 = 0x02 (HS=0), r9 = 0x01 (VS=0), r10 = 0x17.

Счётчик строк Z: в начале каждой строки Z += 1; Z < 480 → активная строка (0xA0); Z = 490 → VS := 0 (0x7C); Z = 492 → VS := 1 (0x8E); Z = 525 → Z := 0 (эта строка гасится). Активная строка: `out r10` (первая загрузка), 79 раз `out r5; nop; nop; out r4` (загрузка каждые 4 такта = 8 точек), затем гашение.

Подсчёт тактов (от первой загрузки = такт 0):

| Участок | Такты ATtiny13 | Точки |
|---|---|---|
| Активная часть (80 загрузок на тактах 0,4,…,316; /MR=0 на такте 321) | 0..319 | 640 |
| Передняя площадка (до `out r8` на 0x330, такт 328) | 320..327 | 16 |
| HSYNC = 0 (0x330 … `out r7` 0x33C, такт 376) | 328..375 | 96 |
| Задняя площадка (до следующей первой загрузки, такт 400) | 376..399 | 48 |
| **Период строки** | **400** | **800** → 31,469 кГц |

Неактивные строки — та же длительность (проверено: путь через 0x6A, цикл 0x6D, 400 тактов от HSYNC до HSYNC).

По вертикали (Z = номер итерации): видимые Z = 1..479 (479 строк), Z = 480..489 — передняя площадка (10), Z = 490..491 — VSYNC = 0 (2 строки), Z = 492..524 и Z = 525→0 — задняя площадка (34). Всего 525 строк → 59,94 Гц. Полярность обоих синхроимпульсов **отрицательная**. Фактически стандарт 640×480@60 (VESA: 480 + 10 + 2 + 33), со сдвигом: одна строка растра погашена вверху, т.е. видимая область начинается на 1 строку позже стандартной, и 480-я строка текста не видна (см. 2.3).

### 2.2 МК ВГА ATmega328P (DD8 в 3.x, DD9 в 6.x), прошивка 1.24 [код]

Карта флеш: 0x0000–0x07FF — код (страницы 0x00–0x0F; загрузчик пишет `A=5:00-0f`), 0x0800–0x6BFF — шрифты (страницы 0x10–0xD7, `A=5:10-d7`), 0x7E00 — загрузчик (`criss0/DD8.hex`). ОЗУ: 0x0100–0x08CF — буфер экрана 2000 байт, 0x08D1–0x08F0 — таблица «страница шрифта для строки текста» (32 байта).

Прерывания: PCINT1 (0x10 → 0x68) на **подъёме** VSYNC (PC3 = 1): сброс счётчиков, состояние r20 = 1 (отсчёт задней площадки). PCINT0 (0x0C → 0x84) на **подъёме** HSYNC (PB0 = 1):
- r20 = 1: r18 += 1; при r18 = 33 → r20 = 0 (дальше активные строки); PORTD = 0;
- r20 = 0: вывод строки: задержка, затем для каждого знака `ld r30,X+; lpm r17,Z; out PORTD,r17` (ZH = r31 = страница строки шрифта, ZL = код символа) — 6 тактов, через каждые 3 знака `nop` (19 тактов / 3 знака при 20 МГц = 949,9 нс против 953,3 нс у ГСС; расхождение < 2 тактов за строку); после последнего знака PORTD = 0;
- в конце строки: r23 (строка растра в знаке) += 1; если r23 = r6 → следующая строка текста: r22 += 1, r31 = таблица[0x08D1 + r22], X = начало строки + r14; иначе r31 += 1 (следующая строка шрифта). При r22 = r7 → r20 = 2 (до следующего VSYNC ничего не выводится).

Первая выведенная строка (ВГА) приходится на Z = 1 ГСС (33 подъёма HSYNC после подъёма VSYNC на Z = 492: Z = 492…524, следующая строка Z = 525→0 — прерывание, вывод идёт в Z = 1). Первая загрузка 74HC166 — через 48 точек после конца HSYNC; ВГА успевает выставить PORTD примерно через 1,6 мкс после фронта (≈ 32 такта) — до загрузки на 1,907 мкс. Итог: **столбец 0 = точки 0..7 видимой области**, все 80 столбцов на стандартных местах.

Режим задаётся байтом VSTAT (= регистр D0 КВУ), подпрограммы 0x66C / 0x6CC:

| VSTAT | Действие |
|---|---|
| 0x00 | **сон**: PC2 = 0 (ATtiny13 в сбросе, синхроимпульсов нет — монитор уходит в ожидание), PORTD = 0 [0x66C–0x676] |
| строк = VSTAT>>3 | 0..24 → **24×80, 20 строк растра** (r7=24, r14=80, r6=20; число строк 1..23 игнорируется!); 25..29 → **25×80, 19 строк**; 30 → **30×64, 16 строк**; 31 → **31×64, 15 строк** [0x680–0x6CA] |
| стр. = VSTAT&7 | база страниц шрифта (ZH первой строки растра): 0 → 0x08 (CP0), 1 → 0x1C (CP1), 2 → 0x30 (CP2), 3 → 0x44 (CP3), 4 → 0x58 (CP4), **5 → 0x0A (CP0 со 2-й строки растра)**, **6 → 0x5A (CP4 со 2-й строки)**, **7 → особый режим** [0x6CC–0x7D8] |
| особый режим (7) | VSTAT принудительно = 0xC7 (24×80×20); для каждой из 25 строк текста страница = (байт буфера 0x0880 + строка) & 7: 1..4 → CP1..CP4, иначе CP0 (страницы 5/6 здесь недоступны). Таблица пересчитывается каждый кадр, пока режим 7 [0x70E–0x752, 0x658–0x664]. Буфер 0x0880 = смещение 1920 = Z80 0xFF80 (как в «ESC G S»). |

Видимые строки растра шрифта (номера строк внутри 20-строчного символа):

| Режим | Строк текста | Строк растра на знак | Строки шрифта | Всего строк растра |
|---|---|---|---|---|
| 24×80, стр. 0–4 | 24 | 20 | 0..19 | 480 (последняя, 480-я, гасится ГСС) |
| 25×80, стр. 0–4 | 25 | 19 | 0..18 | 475 (+4 пустых снизу) |
| 25×80, стр. 5/6 | 25 | 19 | 2..20 (строка 20 = страница 0x1C = строка 0 CP1, для стр. 6 — страница 0x6C за концом шрифтов, во флеш там стёртые 0xFF [дог.]) | 475 |
| 30×64, стр. 5 | 30 | 16 | 2..17 | 480 |
| 31×64, стр. 5 | 31 | 15 | 2..16 | 465 (+14 пустых) |
| 30/31×64, стр. 0 | 30/31 | 16/15 | 0..15 / 0..14 | — (у CP0 буквы на строках 4..13, видно все) |

ЦПУ 4.67 формирует VSTAT = (строки<<3) | (CRT_SETTINGS & 7) (cpu-io.md §5). Сочетания «30/31 строк + стр. 5/6» — то, что даёт `ESC G 6/7/8` [дог. по документации: «знакогенератор 0/4 и 30/31 строка»].

Строк буфера: в 80-столбцовых режимах строка = 80 байт (смещение = строка×80 + столбец), в 64-столбцовых — 64 байта. Буфер всегда 2000 байт; в 31×64 используется 1984.

**64 столбца — видно только 61.** Ветка 0x2F6–0x48E содержит 61 тройку `ld/lpm/out` и затем `out PORTD,r3` (0). Объяснение — нехватка места: 0x2F6 + 61×6 + 20×2 (`nop`) + 4 = 0x490 — ровно начало кода сброса, а шрифты прибиты к 0x0800; 64 тройки не помещаются. Начало вывода то же, что в 80-столбцовом (одинаковые 3 такта на ветвление). Значит: столбцы 0..60 на точках 0..487, 61..63 не показываются, справа 152 точки чёрного. Для ядра: либо воспроизвести (совместимость «как в железе»), либо показывать 64 (если софт рассчитывает на 64 — ЦПУ видит 64-столбцовый экран). **Решение за пользователем.**

Курсор у ВГА отсутствует (вставляет КВУ, §4.3). Инверсия у ВГА отсутствует: «атрибут инверсии» CP2/CP3 = символы 0x80–0xFF в таблице нарисованы инверсными.

### 2.3 Приём экрана от КВУ (протокол на проводах ВГА) [код vga 0x600–0x66A, cpd 0xA00–0xA9A]

SPI ВГА: ведомый, режим 0, старшим битом вперёд (SPCR = 0x40). Цикл главной программы ВГА (вне прерываний строк, т.е. фактически в гасящих интервалах):

1. однократно при старте: SPDR := 0x52 ('R'), импульс PC0, ждать SPIF, принятый байт отбросить;
2. для каждого из 2000 байт: SPDR := 0xFF, импульс PC0 (низкий, 5 тактов), ждать SPIF, записать байт в 0x0100+i;
3. PB1 := 1, SPDR := 0x52, импульс PC0, принять **байт режима** → r11, PB1 := 0;
4. если r11 ≠ прежнего — сменить режим (2.2); если равен и режим 7 — пересчитать таблицу страниц; перейти к п. 2.

КВУ (главный цикл 0xA00): если взведён флаг INT1 (спад PD3 = запрос ВГА) — сбросить, выдать **один** байт: PC3 (SS) = 0, 8 бит старшим вперёд (PC2 = данные, PC0 = такт), читая PC1 (MISO), PC3 = 1. Байт = ОЗУ КВУ[Y], Y += 1; если Y (до увеличения) = D1:D2 (адрес курсора) и r22 < 50 → вместо символа выдаётся **0x00**. Если принятый от ВГА байт = 0x52 → Y := 0x0100. Так как после 2000 байт Y = 0x08D0 (регистр D0), 2001-й байт = VSTAT, а ответ 'R' в этом же обмене возвращает Y на начало: кадр синхронизирован «маркером» 0x52.

Темп обновления копии экрана в ВГА ограничен (байт за проход главного цикла КВУ и только в гашении ВГА) — порядка нескольких кадров экрана в секунду [дог., не измерялось]. Для ядра несущественно: видеоконтроллер ядра читает экранное ОЗУ напрямую; мигание курсора и замена на код 0 — в ядре.

### 2.4 EEPROM ВГА (`vga_328.eep.bin`, 953 байта) [код vga 0x490–0x544]

При сбросе ВГА: байт 0 = VSTAT (здесь 0xC1: 24 строки, CP1 — графика); буфер заполняется 0x00 при CP1, иначе 0x20; затем с адреса 1 текст: 0x1F — конец, 0x0D — следующая строка (X = 0x100 + строк×80), 0x09 — табуляция к адресу, кратному 8 (выход, если дошли до 0x0880), остальное — символ. Содержимое — логотип «CP/M inside» графикой 160×96 (`extract/vga_eeprom_splash.png`). Экран держится, пока КВУ не пришлёт первый кадр.

### 2.5 Знакогенераторы [код]

## 4. КВУ (контроллер внешних устройств, ATmega328P, 20 МГц), прошивка 0.24

Флеш: 0x0000–0x00A0 векторы + обработчики (INT0 0x04, T2OVF 0x24, SPI 0x44), 0x0400 начало, главный цикл 0x0600–0x1A00 (блоки по 0x200), подпрограммы мыши 0x1A04–0x1DC6, таблицы 0x2000–0x2BFF, 0x4400; загрузчик 0x7C00 (`criss*/DD5.hex`). ОЗУ: 0x0100–0x08CF экран 2000 байт, 0x08D0–0x08F3 регистры (порты Z80 D0–F3), 0x08F4–0x08FF — стек (SP = 0x08FF), «порты» F4–FF в КВУ не существуют.

### 4.1 SPI-кадры от ЦПУ (КВУ — ведомый, режим 0, SPCR = 0xC0, прерывание) [код cpd 0x44–0xA0]

Принятые байты пишутся по X в r0, r1, r2 (X = 0 после каждого кадра).

| Первый байт b0 | Кадр | Действие |
|---|---|---|
| 0x80 | 1 байт | сброс приёма (X := 0). ЦПУ шлёт 30 × 0x80 для синхронизации при старте (cpu-io.md) |
| 0x81–0xFF (бит7) | b0, lo, data | экран: адрес ОЗУ = 0x0100 + ((b0 & 7)<<8 \| lo); запись, если < 0x08D0. ЦПУ шлёт старший байт адреса Z80 0xF8..0xFF — т.е. смещение от 0xF800 |
| 0x40–0x7F (бит6) | b0, val | запись регистра 0x08D0 + (b0 & 0x3F) |
| 0x00–0x3F | b0, любой | чтение: после b0 КВУ кладёт в SPDR регистр 0x08D0 + b0, ЦПУ получает его во 2-м байте; если бит5 b0 = 1 (регистры 0x20–0x3F = порты F0–F3 и выше) — регистр после чтения обнуляется |

Ответа «готов» нет; содержимое регистров меняет главный цикл, ЦПУ опрашивает.

### 4.3 Экран и курсор

Экран 80×25 = 2000 байт (в 64-столбцовых — 64×30/31) хранится в КВУ; ЦПУ зеркалирует туда записи Z80 в 0xF800–0xFFCF. При сбросе КВУ экран = пробелы + заставка из EEPROM КВУ (`cpd_start_screen.bin`, адрес 0: текст до 0x1F, 0x0D = новая строка; содержимое: «RIS1715 peripherial controller / (c) Igor S. Reshetnikov, v.0.24 2022 / ———» — первая буква «C» в файле отсутствует) [0x420–0x460].

Курсор: при выдаче в ВГА байта с адресом = D1:D2 и r22 < 50 вместо символа идёт код 0x00. r22 считает тики 10 мс по кругу 0..99 [0x1400–0x140E] → **курсор горит 0,5 с, не горит 0,5 с (1 Гц)**. Форма = символ 0x00 текущей таблицы: в CP0, CP2, CP3 и CP4 (2023-11) — блок 8 точек × строки растра 0..17 (строки 18..19 пустые; в 25-строчном режиме видно 0..17 из 0..18, в 30/31 со стр. 5 — строки 2..17/2..16), в CP1 и CP4 (1.24) — пустой (курсор не виден). Скрытие курсора — ЦПУ ставит D1:D2 вне экрана.

### 4.4 Клавиатура PS/2 [код]

Приём: INT0 по спаду PD2 (CLK), данные PD4 [0x04–0x20]: 1-й фронт (старт) … 9-й — сдвиг в r20 (младшим вперёд), 10-й (чётность) игнорируется — **чётность не проверяется**, 11-й (стоп) → r14 = байт. Таймер 2 (/1024, переполнение 13,1 мс, сбрасывается каждым фронтом) обнуляет приём при обрыве [0x24].

Обработка байта (главный цикл 0x800–0x90C):
- 0xFA — игнор (ACK); 0xFE — повторить посылку светодиодов; 0xE1 — игнор (Pause не поддерживается); 0xE0 → флаг E0 (бит5 r21); 0xF0 → флаг отпускания (бит6);
- отпускание: только модификаторы — 0x12/0x59 (Shift) → бит1 := 0, 0x14 (Ctrl, и E0 14) → бит0 := 0, 0x11 (Alt, и E0 11) → бит4 := 0; прочие отпускания игнорируются;
- E0 + скан 0x69..0x7D → скан := kbd_e0[скан − 0x69]; 0x83 (F7) → 0x02;
- нажатие 0x12/0x59 → Shift := 1; 0x14 → Ctrl := 1; 0x11 → Alt := 1; 0x58 (CapsLock) → бит3 ^= 1 и посылка светодиодов; 0x7E (ScrollLock) → бит2 (РУС/ЛАТ) ^= 1 и посылка светодиодов; NumLock не обрабатывается (цифровая клавиатура всегда цифры, с Shift — функции курсора);
- иначе: символ = kbd_main[...] (§4.5); если CapsLock — символ := kbd_caps[символ]; D3 := модификаторы, D4 := скан, D5 := символ, событие бит0. Модификаторы Shift/Ctrl/Alt хранятся во внутреннем r21 и в D3 попадают только с ближайшей символьной клавишей или переключением Caps/Scroll (0x900). Автоповтор клавиатуры даёт повторные символы. Символ 0 тоже пишется (ЦПУ считает «нет символа»).

Светодиоды [0x600–0x6A6, 0x80E–0x82A]: посылка 0xED + байт (бит0 ScrollLock = РУС, бит1 NumLock = DB.бит6 «мышь активна», бит2 CapsLock), программный вывод на PD2/PD4 с ожиданием ACK.

### 4.5 Таблицы перекодировки [код 0x8CA–0x8EE]

`kbd_main.bin` (флеш 0x2400, 2048 байт): адрес = страница×256 + Ctrl×128 + (скан & 0x7F), где страница = Shift + 2×РУС + 4×Alt (биты 1, 2, 4 регистра D3). Значение — код CP866 (1..31 — функциональные коды, §4.5.1), 0 — клавиша не даёт символа. `kbd_caps.bin` (0x2000): применяется к результату при CapsLock; меняет местами a–z ↔ A–Z, а–п ↔ А–П, р–я ↔ Р–Я (0x80–0x9F ↔ 0xA0–0xAF/0xE0–0xEF), остальное без изменений. `kbd_e0.bin` (0x2100):

|---|---|---|---|---|---|---|---|---|---|---|---|
| → скан | 5C | 5E | 5F | 60 | 61 | 62 | 63 | 64 | 65 | 67 | без изменений (E0 4A → 4A «/», E0 5A → 5A Enter) |

Проверки: скан 0x1C → 'a' (стр. 0), 'A' (Shift), 'ф' (РУС); 0x76 → 27; 0x05 (F1) → 10; 0x07 (F12) → 29; 0x78 (F11) → 28; Ctrl+[ → 27; Ctrl+Alt+цифры клавиатуры → ┌┬┐├┼┤└┴┘─│ (одинарные), + Shift → двойные; Ctrl+Alt+буквы → ░▒▓█▄▌▐▀ и элементы рамок. Команда MPCMD (D6), обрабатывается в главном цикле:

| MPCMD | Действие |
|---|---|
| 0x00 | тишина (TCCR1B = 0) |
| 0x01–0xE0 | проиграть MPBUF: PD = cmd>>5 (пауза, тики), ND = cmd & 0x1F (единица длительности, тики) |
| 0xE1–0xFD | предустановленная мелодия n = cmd & 0x0F (**0xE0 — обычная команда, 0xF0–0xFD тоже предустановки n = 0..13**, документация говорит 0xE0–0xEF): MPCMD := EEPROM[0x100 + 16n], MPBUF[0..14] := EEPROM[0x101 + 16n …], MPBUF[15] := 0x04 |
| 0xFE | непрерывно звучит нота MPBUF[0] до 0xFF |
| 0xFF | стоп |

Нота (байт MPBUF): биты 7..3 = индекс тона, бит2 = SPB (без паузы), биты 1..0 = DI; 0x04 — конец, 0x05 — повтор с начала. Длительность ноты L = ND << DI тиков (×10 мс); тон звучит L − P тиков, затем P тиков тишина, где P = PD, если SPB = 0, иначе 0. Тишина включается при равенстве оставшегося счётчика и P (0x1284): при L = P нота молчит целиком, при **L < P паузы нет вовсе** (тон звучит все L тиков). Конец (0x04, команда 0xFF или 16 нот без 0x04): MPCMD := 0, таймер 1 стоп, PB1 := 0. **Событие бит3 (F0) ставится только в случае «16 нот без 0x04»** [0x129A → 0x12E8]; конец по 0x04 и по 0xFF идёт на 0x12EA мимо `sbi GPIOR0,3`, поэтому предустановленные мелодии (MPBUF[15] = 0x04) события не дают. В cpu-io.md §8 бит3 назван «мелодия закончилась» — по коду это не так. Пример из справочника (`port[214]:=10`, ноты 121,145,…) — ND = 10 → восьмая = 100 мс.

Предустановленные мелодии — в EEPROM КВУ с 0x100 (16 по 16 байт). В поставке их нет: `cpd_start_screen.bin` = 150 байт (адреса 0x000–0x095); стёртая EEPROM = 0xFF → команда 0xFF = стоп, т.е. мелодии молчат [дог.]. Во флеш КВУ мелодий нет (флеш 0x2C00–0x43FF пуст). Звуковой сигнал ^G делает ЦПУ.

### 4.7 RS-232 [код 0x1000–0x1046, 0x4BA–0x4CE]

RS-232 — **в КВУ** (USART0, PD0/PD1 → MAX232). Старт: 9600 8N1 (UBRR0 = 129 при 20 МГц, U2X = 0), без прерываний. Каждый проход цикла: F1 |= UCSR0A; принят байт → F3 := UDR0, событие бит7; TXC → событие бит6; если DF ≠ 0 и UDRE → UDR0 := F2, DF −= 1. Скорость — через SYSRQ: SYSAA = 0xC4 (UBRR0L), SYSVV = делитель, команда 3 (запись 16-бит, UBRR0H := 0) (§4.10); делители справочника: 129/86/64/42/32/21/15/10 → 9600…115200 (при 20 МГц: 9615, 14368, 19231, 29070, 37879, 56818, 78125, 113636 бод). Второй последовательный канал (XP2 «TTY») — UART1 самого ЦПУ (cpu-io.md).

### 4.8 I2C / GPIO (TWCMD D7) [код 0xC00–0xE1A]

TWI: 100 кГц (TWBR = 92, предделитель 1). Тайм-аут: старшие биты r16 += 0x40 каждые 10 мс, при r16 & 0xC0 = 0xC0 → ошибка 0xFF (≈ 20–30 мс).

| D7 | Действие |
|---|---|
| 0x00–0x0F | ничего (результат прошлой команды) |
| 0x10–0xDF | простая команда PCF8574: D7 = адрес SLA+R/W целиком (C3..C0 A2..A0 RW). Запись: START, SLA+W (ждёт 0x18), данные D8 (ждёт 0x28), STOP. Чтение: START, SLA+R (ждёт 0x40), байт с NACK (0x58) → D8, STOP. Итог D7 = 0; ошибка — D7 = 1, D8 = статус TWSR&0xF8 или 0xFF (тайм-аут) |
| 0xE0, 0xE1, 0xE2, 0xE4 | мышь (§4.9); прочие 0xEx → D7 := 0 |
| 0xFE | сброс TWI: TWCR = 0x80, TWSR (0xB9) := 0, PC4/PC5 — входы без подтяжки; D7 := 0 |
| 0xFD | расширенный режим: пары (код, значение) в MPBUF E0–EF; коды 0x08 START (значение = SLA+RW), 0x10 RESTART, 0x18/0x20/0x28 WRITE, 0x40 READ RQ, 0x50/0x58 READ, 0x00 — STOP и конец. Прочитанный байт пишется в значение следующей пары (как в справочнике) |
| 0xF0–0xFC, 0xFF | D7 := 0 |

### 4.9 Мышь PS/2 [код 0x1A04–0x1DC6, 0xC42–0xC9C]

Те же линии, что I2C: PC4 = DATA, PC5 = CLK, программно, I2C на время команды выключается. Посылка байта: CLK = 0 110 мкс (цикл 0x1A04 = 20 тактов = 1 мкс на итерацию), затем DATA = 0 и CLK отпущен, старт, 8 бит, чётность, стоп; приём: 11 фронтов, ожидание каждого фронта ≤ 10 тиков (100 мс), иначе ошибка (D8 = 2).

| D7 | Действие | Результат |
|---|---|---|
| 0xE0 | послать 0xF0 (remote mode), ждать 0xFA; D9 := DA := 0; DB |= 0x60 (MSS, LCR → NumLock горит) | D7 = 0; ошибка — D7 = 1, D8 = принятый байт / 2 |
| 0xE1 | послать 0xEB (read data), ждать 0xFA, принять 3 байта: D8 := (D8 << 4) & 0xF0 \| (статус & 7) (биты 0 L, 1 R, 2 M; старшая тетрада = прошлое состояние), D9 += dX, DA += dY (8 бит со знаком, 9-й бит знака PS/2 не учитывается, Y вверх +) | D7 = 0 |
| 0xE2 | послать 0xFF (сброс мыши) | D7 = 0, D8 = 0xFF |
| 0xE4 | DB: MSS := 0, LCR := 1 (погасить NumLock) | D7 = 0 |

Перехват: если во время команды мыши пришёл байт от клавиатуры (r14 ≠ 0), обмен прерывается (0x1D18): D7 := 0, D8 = прежнее значение с битом 3 := 0 — состояние мыши не меняется. Установленного бита «AF» = 1, как в справочнике, в коде нет (бит 3 только сбрасывается).

### 4.10 SYSRQ (DB) [код 0x1600–0x1672]

При бите7 = 1, команда = биты 3..0: 1 — SYSVV := data[SYSAA] (пространство данных AVR 0x00–0xFF: регистры, I/O, расширенный I/O, начало ОЗУ); 2 — data[SYSAA] := SYSVV; 3 — data[SYSAA+1] := 0, затем data[SYSAA] := SYSVV (16-бит, старший = 0); 0x0E — SYSAA := 0, SYSVV := 0x18 (версия 0.24); 0x0F — сброс системы (PD7). Затем DB &= 0x70. Отдельно: бит5 (LCR) при свободной линии PS/2 → посылка светодиодов, бит5 := 0. Для ядра: команды 1–3 дают доступ к «железу» КВУ (UBRR, GPIOR1 = маска прерываний 0x4A) — эмулировать нужное подмножество: UBRR (0xC4/0xC5) и GPIOR1 (0x4A).

### 4.11 EEPROM КВУ

0x000–0x095: заставка (`cpd_start_screen.bin`, уплоадер `4=`). 0x100–0x1FF: 16 предустановленных мелодий (формат §4.6), в поставке отсутствуют.

## 5. Модуль цвета CLR (ATtiny84, прошивка 0.5)

Флеш: 0x000–0x1FF — загрузчик (`criss1/DD6.hex`, 0x000–0x241: векторы `rjmp` на 0x200+2i, команды '7' — страница флеш 64 байта (только ≥ 0x200), '8' — EEPROM, тайм-аут → 0x200); приложение 0x200–0xA3F + таблица переходов 0xC00–0xCFF (`clr.hex.bin` содержит образ с адреса 0, область загрузчика там пустая; уплоадер `A=7:08-38`, т.е. страницы 0x200–0xE3F). Такт 20 МГц [код: тот же темп 19 тактов / 3 знака, что у ВГА; дог., что от общего генератора].

### 5.1 Буфер цвета [код clr 0x2B4–0x6E4, 0x76A–0x80E]

ОЗУ 0x0060–0x023F: 24 строки × 20 байт (строка текста k с 0x60 + 20k). Строка — RLE-список: байт = **0x80 | ((длина − 1) << 3) | цвет**, длина 1..16 знакомест, цвет 0..7. Заполнение «по умолчанию»: 5 × (0xF8 | цвет) = 80 знакомест (остальные 15 байт строки не используются). Вывод строки растра (прерывание по подъёму HSYNC, 80 шагов как у ВГА): `subi r21,8; out PORTA,r21`, следующий байт берётся, когда результат становится < 0x80 → каждое знакоместо на PA0..PA2 выдаётся цвет (биты 3..6 PORTA тоже меняются, но эти выводы — входы). Байт без бита 7: 0x00–0x07 дают **17** знакомест цвета b&7 (вычитание проходит 0xF8+c … 0x80+c, затем 0x78+c ≥ 0), 0x08–0x7F — 1 знакоместо. Нулевая строка (загрузка из EEPROM в поставке) = чёрная (5 × 17 ≥ 80).

Геометрия жёстко 24 строки × 20 строк растра (r6 = 20, r7 = 24), отсчёт: VSYNC (PA7) спад → 35 подъёмов HSYNC (2 + 33) → первая строка цвета в той же строке растра, что первая строка ВГА [код 0x262, 0x298–0x2AE]. В режимах 25×80 / 30–31×64 динамический цвет не совпадает со знакоместами — ЦПУ, видимо, переводит CLR в статический режим [дог.].

### 5.2 Режимы

- **Статический** (после сброса и командами 0x00–0x08, 0x7C): PORTA = постоянный цвет на весь экран, прерывания строк выключены, обмен по INT0. Цвет после сброса = EEPROM[0x1FF] (в поставке 0x02 = зелёный — монохромный вид исходной машины).
- **Динамический** (команда 0x7F): включены PCINT по HSYNC/VSYNC, цвет по знакоместам из буфера. Обмен с ЦПУ — только во время строчного синхроимпульса (см. 5.3).

### 5.3 Протокол с ЦПУ [код clr 0x240–0x282, 0x288–0x296, 0x73E–0x75A]

USI в трёхпроводном режиме, внешний такт (ЦПУ — мастер, SPI режим 0 [дог.]). Выборка: спад PB2. Статический режим — по INT0 сразу; динамический — проверяется в начале HSYNC (PCINT по спаду PB1: если PB2 = 0, USI взводится) и закрывается на подъёме HSYNC, т.е. байт должен пройти в пределах строчного импульса (~3,8 мкс). Одновременно с приёмом команды CLR выдаёт по DO **байт состояния**: 0x10 | (r5 & 0x0F) (готов, текущий цвет и бит «режима»), либо 0x00, если ещё занят предыдущей командой; **команда принимается, только если CLR ответил ненулевым** — ЦПУ повторяет, пока не получит ≠ 0 (cpu-io.md: «квитирование по MISO»).

Команды (байт от ЦПУ):

| Байт | Действие |
|---|---|
| 0x00 | статический режим с цветом GPIOR1 (= цвет по умолчанию), заполнить буфер |
| 0x01–0x08 | статический режим, цвет = байт − 1 (0..7), заполнить буфер этим цветом |
| 0x09–0x10 | записать цвет по умолчанию (байт − 9) в EEPROM 0x1FF и GPIOR1 |
| 0x11–0x60 | столбец := байт − 0x11 (0..79) |
| 0x61–0x78 | строка := байт − 0x61 (0..23) |
| 0x79 'y' | очистить строку (цвет по умолчанию r5) |
| 0x7A 'z' | очистить весь буфер |
| 0x7B '{' | прокрутка вверх на строку, нижняя строка — цвет по умолчанию |
| 0x7C '\|' | статический режим, бит3 (PA3 = выход, 1) — «режим цветовых схем» [дог. по ESC r P] |
| 0x7D '}' | ничего |
| 0x7E '~' | загрузить буфер (480 байт) из EEPROM 0x000–0x1DF, перейти в динамический режим |
| 0x7F | динамический режим, буфер заполнить цветом по умолчанию |
| 0x80–0xFF | **закрасить участок**: с (строка, столбец) длиной ((b>>3)&15)+1 знакомест цветом b&7; вставляется в RLE-строку со слиянием соседних одинаковых цветов (не более 20 элементов, иначе отказ); столбец не сдвигается; копирование в рабочий буфер ждёт, пока луч не на этой строке [0x810–0x826, 0x884–0x9DC] |

Соответствие ESC-последовательностей (ESC r S/E/L/P/HRGYBMCW, ESC s n c) этим байтам делает ЦПУ — см. cpu-io.md / прошивку ЦПУ (вероятно S→0x7B, E→0x7A, L→0x79 [дог.]).

### 5.4 Цвета

Индекс 0..7 = чёрный, красный, зелёный, жёлтый, синий, малиновый, циан, белый [док. ESC r / ESC s] ⇒ бит0 = R, бит1 = G, бит2 = B, по одному уровню (RGB111) [дог. по порядку названий и «2 = зелёный» по умолчанию]. Фон чёрный, цвет — у точек символа [дог.: схемы 6.x нет].

### 5.5 EEPROM CLR (`clr_eeprom.bin`, 512 байт)

0x000–0x1DF — сохранённая цветовая картинка (24×20 байт RLE; в поставке нули), 0x1E0–0x1FE — не используется, **0x1FF — цвет по умолчанию = 0x02 (зелёный)**.

## 7. Что это значит для ядра (предложение)

- Видео: счётчик 800×525 на 25,175 МГц (или 25,2), строки текста 24/25/30/31 по 20/19/16/15, ширина 80 (или 61/64 — решить), шрифт 5 × 5120 байт ROM (формат `font_*.bin` или исходный «по страницам»), выбор таблицы на строку текста (режим 7) и сдвиг на 2 строки (стр. 5/6), курсор = подстановка кода 0 с миганием 1 Гц по адресу D1:D2, сон = выключить синхро.
- Регистры КВУ D0–F3 — блок регистров в ядре; клавиатура — таблицы `kbd_*.bin` в ROM ядра или переписать логикой; тоны — делитель от 20 МГц по `cpd_tones.bin`; RS-232 — UART; I2C/мышь — по необходимости.
- Цвет: атрибут 3 бита на знакоместо 80×24 (+ статический цвет), RLE не нужен, если сохранять семантику команд 5.3.

## 8. Открытые вопросы и риски

1. **61 столбец в режимах 64** — подтверждено кодом ВГА 1.24 и объяснено нехваткой флеш под код (§2.2). ЦПУ при этом считает экран 64-столбцовым — столбцы 61..63 на реальной машине не видны. Решить, воспроизводить ли.
2. Строка растра 479 (последняя строка 20-строчного символа в 24-строчном режиме) гасится ГСС; первая видимая строка растра — 2-я по стандарту VGA (сдвиг на 1 строку). Мелочь, решить, повторять ли.
3. Схема 6.x отсутствует: разводка CLR, 74HC173, способ смешивания цвета с точками (И? фон?), источник такта CLR — догадки. Также неизвестно, как в 6.x подключены ВГА/КВУ (README: «номера МК в 6.x не соответствуют схеме 3.x»).
4. Предустановленные мелодии (EEPROM КВУ 0x100+) в поставке нет — содержимое неизвестно; диапазон команд по коду 0xE1–0xFD (не 0xE0–0xEF, как в справочнике).
5. Тактовая ВГА/ЦПУ = 20 МГц выведено из темпа вывода и схемы 3.x; у КВУ 20 МГц подтверждено тремя независимыми константами. Брифинг указывал 8 МГц — не подтверждается.
6. Заставка КВУ начинается с «RIS1715» (буква «C» отсутствует в файле) — так и будет на экране.
7. Пропускная способность обмена КВУ→ВГА и ЦПУ→CLR в реальном времени не измерялась (для ядра не нужна, но влияет на «видимые» эффекты исходника — запаздывание экрана).
8. Перевод ESC r / ESC s / ESC q в байты CLR и выбор статического режима при смене видеорежима — на стороне ЦПУ (cpu-io.md, подпрограмма 0x16800), здесь не разбиралось.
9. Бит «AF» мыши: в 0.24 при перехвате бит 3 D8 сбрасывается, а не ставится (§4.9) — расходится со справочником.
10. Событие «конец мелодии» (F0 бит3) по коду ставится только при исчерпании 16 нот без 0x04 (§4.6) — проверить, как ЦПУ его использует (cpu-io.md считает его концом мелодии).
