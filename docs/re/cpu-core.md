# КРИСС CP/M: ядро эмулятора Z80 в МК ЦПУ (прошивка 4.67)

Источник: `upstream/fw/x/criss.cpu.4.67/cpu.hex.bin` (ATmega1284P), дизассемблер `upstream/dis/cpu467.S`
(сверка с `cpu466.S`). Все адреса — **байтовые** адреса флеш AVR (как печатает objdump), если не сказано иначе.
Адреса ОЗУ AVR пишутся как `SRAM 0x....`. Пометки: **[код]** — проверено по коду, **[догадка]** — вывод/предположение.

Соседние отчёты: порты, SPI-протоколы, источники прерываний, ESC/консольный вывод — `cpu-io.md`;
периферийные МК — `periph.md`. Здесь их тексты не повторяются.

## Кратко

- Эмулятор — «шитый код»: на каждый опкод свой обработчик, таблицы переходов лежат во флеш
  0x1A000..0x1C0FF и при старте копируются в SRAM 0x0A00..0x2AFF; выборка = 16 тактов AVR,
  `LD r,r` = 20 тактов = 1 мкс при 20 МГц [код + расчёт]. Регистры Z80 живут в регистрах AVR,
  F хранится **в формате SREG AVR**.
- ED 00..ED 10 = BIOS 0..16; **ED 11..ED 26 (BIOS 17..38) в 4.67 ничего не делают** (только
  пишут номер в BIOS_LAST_CALL и отладочный вывод) [код]. BOOT (ED 00), WBOOT (ED 01), HOME (ED 08) тоже пустые.
- ED 27 — «быстрый BDOS»: функции 6 и 11 делаются в прошивке, всё остальное — переход на
  **жёстко прошитый 0xCABF** (BDOS образа SCPX/Robotron) [код].
- ED 77 MUL (`A:H:L := HL*A`, **с ошибкой** в средних разрядах), ED 7F DIV (`HL := HL / A`, `A := остаток`),
  ED A4..A7 FL32: IEEE-754 single (add, sub, mul, div): (HL) op (BC) → (HL) [код; соответствие op — почти наверняка].
- Диск: блок SD = `SD_FDD_BASE[диск] * 4096 + дорожка * 20 + сектор / 4`, 128-байтный кусок
  `(сектор & 3) * 128`; один 512-байтный кэш, запись сквозная [код]. Карта: дескрипторы с LBA 0x800,
  загрузочные образы с LBA 0x900 + 0x80·n (124 блока → Z80 0x0000..0xF7FF), старт PC = SP = 0x0100 [код].
- Прерывания Z80: 16 источников, байт-вектор из SRAM 0x36CF+i (настройки в ОЗУ DS1305), IM 0/1/2 и «NMI»
  (вектор 0xDD). Есть заметные отличия от Z80: при DI запрос теряется, нет задержки EI, RETI/RETN
  восстанавливают сохранённые IFF, HALT после прерывания возвращается в HALT [код].
- Блокеры для ядра: нужен IEEE-float (FL32) и снимки состояния в SPI EEPROM 25LC1024
  (загрузка «A/B», Ctrl+Alt+F1/F2 переключение задач). Неожиданного «железа» за BIOS 17..38 нет.

## 1. Регистры Z80 ↔ регистры / ОЗУ AVR

### 1.1 Основной набор [код]

Подтверждено обработчиками `LD rr,nn` (0x060C, 0x07BC, 0x0974, 0x0BD2, DD 21 = 0x4D18, FD 21 = 0x8780),
`EX DE,HL` (0x2972), `EX AF,AF'` (0x06EE), `EXX` (0x22DE), начальным обнулением (0x1117C..0x111AA).

| Z80 | AVR | Примечание |
|---|---|---|
| A | r17 | |
| F | r20 | формат SREG AVR, см. 1.3 |
| B | r10 | |
| C | r22 | |
| D | r12 | |
| E | r13 | |
| H | r14 | |
| L | r15 | |
| IXh / IXl | r8 / r16 | |
| IYh / IYl | r19 / r11 | |
| SP | r29:r28 (Y) | |
| PC | r25:r24 | выдаётся на PORTC (старший) / PORTA (младший) |

### 1.2 Остальное в SRAM [код]

| SRAM | Z80 | Где видно |
|---|---|---|
| 0x0900 | I | LD I,A (0x7642), LD A,I (0x7876), IM 2 (0xE2AA) |
| 0x0901 / 0x0902 | A' / F' (F' тоже в формате SREG) | EX AF,AF' 0x06EE |
| 0x0903 / 0x0904 | B' / C' | EXX 0x22DE |
| 0x0905 / 0x0906 | D' / E' | |
| 0x0907 / 0x0908 | H' / L' | |
| 0x0909 | IFF1 (0/1) | DI 0x2BDC, EI 0x2EC4 |
| 0x090A | IFF2 (0/1) | LD A,I/R: P/V := IFF2 |
| 0x090B | режим IM (0, 1, 2, 3) | ED 46/56/5E/4E… (0x7638, 0x786C, 0x7958, 0x770E) |
| 0x090C | бит 7 регистра R | LD R,A 0x7718 |
| TCNT0 (I/O 0x26) | R биты 0..6 | LD A,R 0x796C: `R = (TCNT0 & 0x7F) \| [0x090C]` |
| 0x090E | байт данных последнего OUT (или A для OUT (n),A) | 0x203E, 0x7500 |
| 0x09A9 / 0x09AA | IFF1/IFF2, сохранённые при приёме прерывания | 0xE26E; восстанавливаются RETI/RETN (0xE000) |

R: TCNT0 считает CLK/8 (TCCR0B = 2, запись 0x111E0) — **R не связан с числом выполненных инструкций**,
это свободно бегущий счётчик 2.5 МГц [код]. LD R,A пишет A в TCNT0 целиком [код].

### 1.3 Формат флагов [код]

F хранится как SREG AVR; результаты ALU берутся прямо `in r20, SREG` (например ADD A,B 0x13EC:
`add r17,r10; in r20,SREG; andi r20,0xAF`).

| бит r20 | флаг AVR | смысл для Z80 |
|---|---|---|
| 0 | C | C |
| 1 | Z | Z |
| 2 | N | S (знак) |
| 3 | V | P/V |
| 4 | S (N⊕V) | мусор, маскируется |
| 5 | H | H |
| 6 | T | N (вычитание): DEC/CP/SUB ставят `ori r20,0xC0` |
| 7 | I | всегда 1 у «нормальных» значений (чтобы `out SREG,r20` перед ADC/SBC не запрещал прерывания AVR) |

Перевод в настоящий байт F Z80 — таблицы в SRAM [код, проверено скриптом]:

- PUSH AF (0x2CC6): F_z80 = таблица SRAM 0x1900[r20]: бит0→0x01 (C), бит1→0x40 (Z), бит2→0x80 (S),
  бит3→0x04 (P/V), бит5→0x10 (H), бит6→0x02 (N), биты 4 и 7 отбрасываются.
- POP AF (0x2B78): r20 = таблица SRAM 0x1A00[F_z80] = 0x80 | обратное отображение.
- **Недокументированные биты F 3 и 5 (X/Y) всегда 0** при PUSH AF и теряются при POP AF [код].
- Таблица чётности SRAM 0x1800: 0x08 (= P/V) для чётного числа единиц [код].
- DAA (0x0AAE): таблицы SRAM 0x1B00..0x2200 (результат) и 0x2300..0x2A00 (флаги), страница выбирается
  H (+1), C (+2), N (+4) [код].

Побочный эффект [код]: после загрузки r20 = 0 (0x11C04), MUL/DIV пишут r20 без бита 7. Пока бит 7 не
вернётся (любая CP/SUB/DEC/POP AF), каждый ADC/SBC/RL… делает `out SREG,r20` и запрещает прерывания AVR
(UART-приём, тик 10 мс). Для FPGA не важно, но так можно объяснить потерю символов TTY.

### 1.4 Служебные регистры AVR [код]

r5 = 0, r9 = 1, r6 = 0xF8 (порог экранной памяти), r2 = 0xFF / r3 = 0xEF (значения PORTD: покой / /RD),
r4 = 0xDF, r0 = 0xFD (0x11058..0x11074). Временные: r1, r18, r21, r23, r26, r27, r30, r31, r7 (копия SREG).
GPIOR2 (I/O 0x2B) = страница таблицы выборки, GPIOR0 (0x1E) = ожидающие прерывания, GPIOR1 (0x2A) = маска
каскада КВУ.

## 2. Таблицы переходов

### 2.1 Построение [код]

- 0x1114C: `RAMPZ = 1` (0x11022), `elpm` из флеш 0x1A000..0x1C0FF → SRAM 0x0A00..0x2AFF (0x2100 байт).
- SRAM 0x2B00..0x2BFF := 0x09, затем (0x11170) 0x2C00..0x2CFF := 0x70 → все 256 входов «таблицы 0x2B»
  указывают на слово 0x7009 = байт **0xE012** (вход обработки прерывания).
- GPIOR2 := 0x0A (0x11178).
- Каждый вход — **адрес слова** для `ijmp`: младшие байты на странице P, старшие на P+1.

Выборка (0x0400) [код]:

```
0400 in   r27, GPIOR2      ; страница таблицы (0x0A или 0x2B = есть прерывание)
0402 out  PORTC, r25       ; префиксы входят сюда с r27 = своей страницей
0404 out  PORTA, r24
0406 out  DDRB, r5         ; шина данных на вход
0408 out  PORTD, r3        ; /RD = 0
040A adiw r24, 1           ; PC++
040C in   r26, PINB        ; опкод
040E out  PORTD, r2
0410 ld   r30, X           ; X = r27:r26
0412 inc  r27
0414 ld   r31, X
0416 ijmp                  ; 16 тактов от 0x0400 до входа в обработчик
```

| Страницы SRAM | Таблица | Вход из |
|---|---|---|
| 0x0A/0x0B | основная | GPIOR2 |
| 0x0C/0x0D | CB | CB 0x1D0E: `ldi r27,0x0C; jmp 0x402` |
| 0x0E/0x0F | DD | DD 0x2444 |
| 0x10/0x11 | ED | ED 0x2A5C |
| 0x12/0x13 | FD | FD 0x2FAE |
| 0x14/0x15 | DDCB | DD CB 0x60C6: смещение d → r23, затем `ldi r27,0x14; jmp 0x402` |
| 0x16/0x17 | FDCB | аналогично |
| 0x18 | чётность | |
| 0x19 / 0x1A | SREG→F / F→SREG | |
| 0x1B..0x2A | DAA | |
| 0x2B/0x2C | «прерывание»: все входы = 0xE012 | GPIOR2 = 0x2B ставят ISR AVR (0x112) |

Вход 0x0400 = «NONI»: команда считается выполненной, все прочитанные байты префикса/опкода съедены.

## 3. Функции BIOS / BDOS / MUL / DIV / FL32

### 3.1 BIOS 0..16 [код]

Регистры — Z80. «IOBYTE» здесь — байт прошивки CON_IOBYTE (SRAM 0x3F01, по умолчанию 0x11), а **не**
байт CP/M по адресу 0x0003. Биты: 0 вывод на экран, 1 вывод TTY (UART1), 2 вывод LAN, 3 вывод LST,
4 ввод клавиатура, 5 ввод TTY, 6 ввод LAN, 7 ввод LST (документация + ветки 0xE5C4, 0xEDDA).

| # | ED | Вход | Выход | Поведение |
|---|---|---|---|---|
| 0 BOOT | 00 | — | — | ничего (0xE4CC) |
| 1 WBOOT | 01 | — | — | ничего (0xE4CE). Тёплый старт делает Z80-код образа |
| 2 CONST | 02 | — | A = 0xFF есть символ / 0x00 | 0xE4D0: опрос TTY/LAN/LST по IOBYTE.5..7 в буфер SRAM 0x37B8 (счётчик 0x37B7, до 32); если буфер не пуст → 0xFF; иначе при IOBYTE.4 спрашивает КВУ (рег. 5) |
| 3 CONIN | 03 | — | A = символ (+ см. `cpu-io.md` §7: B, C, D, E тоже меняются у платформ) | 0xE4F2: берёт из буфера 0x37B8; иначе КВУ. **Нет символа → PC −= 2** (0xE516): трап исполнится снова, т.е. ожидание «прерываемое». Горячие клавиши (модификаторы & 0x13 = 0x11 = Ctrl+Alt): Del (скан 0x61) → системная консоль 0x18802; F1 / F2 (скан 0x05 / 0x06, если есть EEPROM) → обмен задачами через EEPROM (5.4); NumLock (0x77) → 0xFEC2. Пишет CON_LAST_CHAR 0x3F16, MODK 0x3F17, KACT 0x3F18 |
| 4 CONOUT | 04 | C = символ | — | 0xE5B4: по IOBYTE.1/2/3 в TTY/LAN/LST; IOBYTE.0 → экран + ESC-разбор (`cpu-io.md` §12) |
| 5 LIST | 05 | C | — | 0xE644: по битам [0x3F58]: 0 → LPT (КВУ), 1 → TTY, 2 → LAN, 3 → LST |
| 6 PUNCH | 06 | C | — | 0xE660: по битам 0..3 [0x3F48] (PR_IOBYTE) |
| 7 READER | 07 | — | A = символ **или 0, если нет** (не ждёт) | 0xE67C: опрос по битам 4..7 [0x3F48] в буфер 0x3797 (счётчик 0x3796), затем 0xE8D6 выдаёт первый |
| 8 HOME | 08 | — | — | ничего (0xE698); дорожка **не** сбрасывается |
| 9 SELDSK | 09 | C = диск | A = C, **HL = 0xDEA0 + 16·C** | 0xE69A: [0x3F0F] := C. Проверки нет. 0xDEA0 — таблица DPH образа SCPX; CP/M 2.2 КРИСС сам переписывает HL (`CPM22.Z80` `_SELDSK`) |
| 10 SETTRK | 0A | BC | — | [0x3F10] := B, [0x3F11] := C (старший байт первым). В расчёте блока используется **только C** |
| 11 SETSEC | 0B | C | A = C | [0x3F12] := C |
| 12 SETDMA | 0C | BC | — | [0x3F13] := B, [0x3F14] := C |
| 13 READ | 0D | — | A = 0; A = 2 если SD_TYPE = 0 | 0xE6DA, см. 4 |
| 14 WRITE | 0E | (C = тип записи игнорируется) | A = 0; A = 2 если SD_TYPE = 0 | 0xE786, см. 4 |
| 15 LISTST | 0F | — | A = 0xFF всегда | 0xE7F6: опрашивает приём с LST-каналов по [0x3F58], байт → [0x3F19] (LST_LAST_CHAR) |

Ошибки SD при чтении/записи в A **не возвращаются** (только «нет карты» = 2) [код: 0xE76A, 0xE7D6].

### 3.2 BIOS 17..38 [код]

В 4.67 и 4.66 цепочка 0xE42E проверяет только 0x00..0x10 и внутренние 0xF0, 0xF1, 0xF9..0xFF. ED 11..ED 26
доходят до `ret` 0xE4CA: побочные эффекты — только `[0x3F2E] := n` и отладочная строка в TTY (0x1608E),
если включено «BIOS CALL» в системной консоли. Для FPGA: **2-байтный NOP**, номер можно положить в BIOS_LAST_CALL.

Внутренние номера (Z80 их вызвать не может; вызываются из прошивки через 0xE400/0xE404) [код]:

| № | Адрес | Что делает |
|---|---|---|
| F0 | 0xE884 | положить C в буфер ввода консоли 0x37B8 (используется ESC k) |
| F1 | 0xE8B0 | положить C в буфер READER 0x3797 |
| F9 | 0xE610 | вывод символа на экран без управляющих кодов |
| FA / FB / FC | 0xF2AE / 0xF246 / 0xF1C0 | экранные операции (см. `cpu-io.md` §12) [догадка] |
| FD | 0xE81E | запись C в видео-ОЗУ по VIDEO_CURSOR + 0xF700 (т.е. 0xF800 + смещение) |
| FE | 0xEC2C | переинициализация экрана (режим строк/кодовая страница, VIDEO_END) |
| FF | 0xF156 | (вызывается при старте и выходе из консоли) [догадка: перерисовка/курсор] |

### 3.3 ED 27 — BDOS (0x1005C) [код]

- `[0x3F40] := C` (BDOS_LAST_CALL), отладочный вывод при `[0x3F2A].2`.
- C = 11 (статус консоли): BIOS 2; A := 1 если символ есть, иначе 0; возврат за ED 27.
- C = 6 (прямой ввод-вывод): E ≠ 0xFF → CONOUT(E); E = 0xFF → CONST, если есть — CONIN (A = символ), иначе A = 0.
- Иначе: **PC := 0xCABF** — продолжение BDOS в образе SCPX (system.bin.003: 0x0005 `JP C306` → `JP CAB4`;
  0xCAB4: `ED 27`, `RET`; 0xCABF — начало кода BDOS `LD (CDEA),DE`). В CP/M 2.2 КРИСС (`CPM22.bin`) ED 27 нет.
- Для FPGA: если ED 27 эмулировать, адрес 0xCABF жёсткий (то же в 4.66, 0xFFD8).

### 3.4 MUL / DIV [код, проверено моделью на Python]

**ED 77 MUL** (0x7DFC). Вход HL, A. Выход A:H:L (24 бита). Флаги: F := 0, затем C := (A ≠ 0), Z := (HL = 0);
остальные биты (S, P/V, H, N, бит7 SREG) = 0. Точная формула кода:

```
p   = L * A;  pl = p & 0xFF;  ph = p >> 8
s   = H + ph; c1 = s >> 8;    h2 = s & 0xFF
q   = h2 * A
L' = pl;  H' = q & 0xFF;  A' = (c1 + (q >> 8)) & 0xFF
```

Это **ошибка прошивки**: умножается уже изменённый H. Верно только если `hi(L*A) = 0`
(например 0x012C·3 = 0x000384 верно, 0x01FF·2 даёт 0x0004FE вместо 0x0003FE). Использование в образах
не найдено (поиск ED 77 в system.bin.003 и CPM22.bin — только данные).

**ED 7F DIV** (0x7EF4): беззнаковое 16/8 (алгоритм AVR200 div16u). H:L := HL / A, A := остаток (младший байт).
Флаги: **старый F не сбрасывается** (`ldi r21,0` вместо r20), к нему OR-ом добавляются C := (A ≠ 0)
и Z := (HL = 0). Деление на 0: HL := 0xFFFF, A := L исходного (проверено моделью: HL = 0x1234 → A = 0x34).

### 3.5 FL32 0..3 (ED A4..A7) [код; соответствие операций — почти наверняка]

0x176E4: 4 байта из (HL) → SRAM 0x3F34..37 (операнд 1, младший первым), 4 байта из (BC) → 0x3F38..3B (операнд 2),
код `[0x3F33] := n`, вызов 0x175B2 (сохраняет все регистры AVR, свой стек 0x4080), результат 0x3F3C..3F
→ **(HL)..(HL+3)**. HL, BC, A, F не меняются. Блок 0x3F33..0x3F3F = FLIB_CMD (смещение 51, 13 байт).

Формат: IEEE-754 single little-endian (функции — `fp-bit.c` GCC: unpack 0x18166, _fpadd_parts 0x1791C, pack 0x17FBC).

| n | ED | [0x3F33] | функция | операция |
|---|---|---|---|---|
| 0 | A4 | 0x80 | 0x17C16 | (HL) + (BC) |
| 1 | A5 | 0x81 | 0x17BB4 (меняет знак 2-го, затем сложение) | (HL) − (BC) |
| 2 | A6 | 0x82 | 0x17C70 | (HL) × (BC) [догадка по структуре, без запуска] |
| 3 | A7 | 0x83 | 0x17E64 | (HL) / (BC) [догадка по структуре] |

После работы `[0x3F33]` = 0x80+n (бит 7 = «выполнено»). Те же операции доступны через порт FF (`cpu-io.md` §6.1).

## 4. Диск: CP/M → блоки SD [код]

### 4.1 Расчёт блока (0xEB62)

```
slot  = SD_FDD_BASE[BIOS_DISK]           ; байт SRAM 0x3F1A + [0x3F0F]
LBA   = slot * 4096                      ; 4096 блоков по 512 = 2 МБ на «слот»
      + [0x3F11] * 20                    ; только младший байт дорожки, 20 блоков = 80 секторов CP/M
      + ([0x3F12] >> 2)                  ; сектор (0-базный, SECTRAN = тождество)
offset_in_block = ([0x3F12] & 3) * 128   ; внутри 512-байтного буфера SRAM 0x3000..0x31FF
```

- Переносы из дорожки/сектора в старший байт LBA не идут (`adiw r26`), но для дорожки ≤ 204 их и не бывает.
- Внутри образа: смещение байта = (дорожка·80 + сектор)·128, т.е. образ 819 200 байт = 80 дорожек × 80 секторов
  (DPB CP/M 2.2 КРИСС: SPT 80, BSH 4, DSM 0x185, DRM 0x7F, OFF 2 — `CPM22.Z80`; cpmtools «40 × 160» — та же линейка).
- Карты SDSC: если в OCR нет CCS (`[0x3F2F].6 = 0`, 0x121FE), LBA умножается на 512 (0x124AA).
- По умолчанию SD_FDD_BASE[0..15] = 1..16 (A: = слот 1 …). **Каждая переинициализация SD (0x12064) снова
  ставит 1..16** — в том числе пункт «S» консоли.

### 4.2 Кэш и запись

- Кэш один: номер блока в SRAM 0x0933..0x0936 (LE). Совпало → без чтения (0xEBB8). Иначе CMD17 в буфер 0x3000 (0x121D8).
- READ: копия 128 байт буфера → Z80 [DMA] (с проверкой экрана при записи, 0xE710).
- WRITE: чтение блока при промахе, 128 байт из [DMA] в буфер, **сразу CMD24** (0x12312) — сквозная запись,
  отложенной записи нет.
- Сброс кэша (0x12014, номер := 0xFFFFFFFF) — после консоли, загрузки снимка EEPROM.
- Ошибки CMD17/CMD24 только пишутся в [0x3F30]/[0x3F32] (отладка), Z80 их не видит.

### 4.3 Разметка карты

| LBA (блоки по 512) | Содержимое | Где в коде |
|---|---|---|
| 0x0800 | дескриптор карты (имя) | 0x11974, консоль 0x1895E |
| 0x0800 + HH, HH = 0x01..0xEF | дескриптор диска HH (в утилите r1715sd «DISK HH−1») | консоль 0x18998 (показывает 0x01..0x1E) |
| 0x08F0 + n, n = 0..15 | дескриптор загрузочного образа n («LOAD n») | 0x119C0 (смотрит только n = 0..9) |
| 0x0900 + 0x80·n | загрузочный образ n, 64 КБ в файле, читается **124 блока** | 0x11B26 |
| slot·0x1000 | образ диска слота slot (1..255; утилита пишет 0x01..0xEF) | 0xEB62 |

Дескриптор: 512-байтный блок, с байта 0 — имя в CP866, кончается 0 (печать 0x11254). Пустое имя (первый байт 0)
= «нет». Поле размера прошивка **не читает** [код]; что ещё лежит в дескрипторе — неизвестно (вопрос 3).

## 5. Загрузка

### 5.1 От RESET до Z80 [код]

1. 0x012E: стек AVR 0x40FF; `call 0x11000` (0x1100C: порты, UART1 115200 8N1 (UBRR1 = 10), таймеры,
   PCINT PD0/PD6/PD7, очистка SRAM 0x0100..0x407F, сисперем.: курсор 1,1, 24×80, CON_IOBYTE = 0x11,
   INT_MASK = 0, заполнение всех 64 КБ внешнего ОЗУ байтом 0x20, 0x11128).
2. `call 0x16A0E` (инициализация вывода, `cpu-io.md`), `call 0x11004` → 0x1116E (таблицы, регистры Z80 := 0,
   I/IFF/IM := 0, TCCR0B = 2), `call 0x11008` → 0x11510 (загрузчик ниже), `rjmp 0x400`.
3. 0x11510: пауза; опрос КВУ (ответ ≠ 0xFF → HW_FOUND.7; если нажат ESC — IOBYTE |= 0x22, т.е. консоль ещё и в TTY);
   баннер «CRISS CP/M main CPU module … Version 4.67»; тест ОЗУ 0x0000..0xF7FF (HW_FOUND.0); модуль цвета CLR
   (HW_FOUND.1); RTC DS1305 (HW_FOUND.3, чтение 96 байт ОЗУ RTC → SRAM 0x3690..0x36EF и раскладка настроек);
   LAN ENC28J60 (HW_FOUND.5); CAN (HW_FOUND.6); EEPROM 25LC1024 (команда RDSR 0x05, HW_FOUND.4).
4. SD (0x12064): CMD0, CMD8 0x1AA (R1 → SD_TYPE, принимаются 1, 4, 5), CMD55+ACMD41 (HCS), CMD58 (OCR → 0x092F..).
5. «Loading OS image source»: читает дескриптор карты 0x800 («Found bootable SD card, ID: имя»), перебирает
   дескрипторы 0x8F0..0x8F9, печатает `n = имя` для непустых.
6. Выбор (0x11A40):
   - КВУ нет (HW_FOUND.7 = 0): один образ → он; иначе есть EEPROM → блок EEPROM 1; иначе повтор.
   - КВУ есть: один образ и нет EEPROM → «Only one image found, loading it.»; иначе «Please select boot option:» —
     строка из одного символа + Enter: `0`..`8` → образ n (**`9` отвергается**, хотя образ 9 печатается),
     `A`/`B`/`a`/`b` → снимок EEPROM 1/2, пустой Enter → заново инициализировать SD, прочее → «Bad loading block index».
   - Нет ни SD, ни образов: «No boot source found, replace SD-card:» → ждёт клавишу → повтор.
7. Загрузка образа n (0x11B26): блоки 0x900+0x80·n … +123 → Z80 0x0000..0xF7FF (видео-ОЗУ F800..FFFF не трогается).
   «Starting from address 0x100», внутренние BIOS FE, FF; **PC := 0x0100, SP := 0x0100, A = C = D = F(r20) = 0**;
   прочие регистры не гарантируются (например IXh = номер последнего найденного образа, 0x119EC).
8. 0x11C06: IOBYTE |= байт RTC 0x3691 (без КВУ — биты ввода/вывода консоли снимаются, `andi 0xEE`),
   PR_IOBYTE [0x3F48] := RTC 0x36C2, [0x3F58] := RTC 0x36E4; `sei`; GPIOR2 = 0x0A; переход в 0x0400.

Образ SCPX (system.bin.003) по 0x0100 имеет `JP 0005` → BDOS с C = 0 → сброс системы → WBOOT. CP/M 2.2 КРИСС
по 0x0100 — `JP BOOT` (свой холодный старт). Холодный старт SCPX (0xD942) ставит `I = 0xF0; IM 2; EI` [код Z80].

### 5.2 Тёплый старт [код]

BIOS 1 в прошивке пустой. Оба образа делают тёплый старт сами без чтения диска:
`CPM22.Z80 _WBOOT: ld sp,80h; call START_OS_INIT; jp CCP`, SCPX 0xD9A1: `ld sp,80h; call 0xD9AA; jp 0xC32B`.
**CCP/BDOS должны оставаться в ОЗУ** — образ ОЗУ целиком, загрузки CCP с дорожек нет.

### 5.3 Системная консоль Ctrl+Alt+Del (0x1882A) [код]

Вход из CONIN (только когда программа ждёт ввод). Сохраняет регистры Z80 в SRAM 0x3776..0x3785
(A, F, B, C, D, E, H, L, IXl, IXh, IYl, IYh, SPl, SPh, PCl, PCh), рисует прямо в видео-ОЗУ Z80 (0xF940…).
Пункты (строки 0x1966C..):

| Клавиша | Действие |
|---|---|
| A..D | выбор образа для дисков A..D: список дескрипторов 0x801..0x81E (30 шт.), выбор → SD_FDD_BASE[диск] := 1..30 |
| S | переинициализация SD (и сброс SD_FDD_BASE в 1..16) |
| I | IOBYTE: CON (выводы A–D, вводы E–H), PUNCH/READER (I–P), LIST (Q–T), SD (U–X), мышь (Y) |
| U | отладка: вывод в TTY (порты, BDOS, BIOS, SD, коды CON, IRQ, трассировка Z80), точка останова, шаг |
| H | оборудование: платформа (HW_FLAG 0x3F00, таблица 0x16A10: CRISS 3.x, Robotron RU/EN, Kaypro, TRS-80, Kaypro 8bit, VT100) задаёт строки/столбцы/CRT_SETTINGS; **скорость ЦП A..F = 100/75/60/45/30/15 %**; запреты |
| R | RTC и S-ROM: время, дата, MAC/IP, пароли, **векторы прерываний** (16 шт.), PIN |
| E | EEPROM: RAM ↔ ROM #1/#2 (снимки), стирание |
| V | дамп SRAM AVR 0x0100..0x087F на экран |
| Z | «HALT PROGRAM»: сохранённый PC := 0x0002 → после выхода CONIN делает PC −= 2 → **PC = 0x0000** (тёплый старт) |
| ESC | восстановить регистры (0x188D2) и вернуться в CONIN (трап повторится) |

### 5.4 SPI EEPROM 25LC1024 (128 КБ) [код]

Не «ПЗУ с ОС», а **два слота снимков** по 64 КБ (r17 = номер слота → старший байт адреса EEPROM).
Сохранение 0x18D4A: 256 страниц ОЗУ Z80 0x0000..0xFFFF; затем в последнюю страницу (0xFF00..) с конца
дописывается состояние: регистры 0x3776..0x3786, SRAM 0x0900..0x090E (I, теневые, IFF, IM, R7, данные OUT),
сисперем. 0x3F05..0x3F0F (экран, курсор, диск), 0x3F00..0x3F02. Загрузка 0x18D36 — обратно.

Используется: загрузка `A`/`B` (0x11BCE: загрузить слот, сброс кэша SD, восстановить регистры, PC −= 2),
Ctrl+Alt+F1 = сохранить в слот 0 и загрузить слот 1; Ctrl+Alt+F2 = наоборот (0xE55E..0xE590, «переключение задач»),
меню консоли E. Без EEPROM (HW_FOUND.4 = 0) F1/F2 игнорируются. ROM ОС как такового нет.

### 5.5 Без SD

READ/WRITE возвращают A = 2, если SD_TYPE = 0 [код]. Загрузчик ждёт карту или снимок EEPROM (5.1 п. 6).

## 6. Прерывания Z80

Источники и биты КВУ — в `cpu-io.md` §8 (там то же самое, сверено). Здесь — сторона ядра Z80 [код].

1. ISR AVR ставят биты GPIOR0: бит0 PD7 (LAN), бит2 PD6 (RTC), бит3 PD0 (каскад КВУ), бит6 USART1 UDRE (TTX),
   бит7 USART1 RX (TRX). Хвост 0x0102: `GPIOR0 &= [0x3F04]`; если ≠ 0 → GPIOR2 := 0x2B. Незамаскированные биты
   теряются сразу.
2. Следующая выборка основной таблицы уходит в 0xE012 (в середине префиксной команды и внутри LDIR/CPIR… — нет:
   блочные команды крутятся целиком в одном обработчике, 0x8202).
3. 0xE020: при бите 3 читается регистр КВУ 0x20 & [0x3F03] → GPIOR1 → источник 0..7; иначе биты GPIOR0 → 8, 9, 10,
   12, 13, 14, 15 (бит → номер: 0→8, 1→9, 2→10, 4→12, 5→13, 6→14, 7→15). Бит источника гасится.
4. Байт V = SRAM [0x36CF + номер] (ОЗУ DS1305 0x5F.., задаётся в консоли «IRQ VECTORS»).
5. V = 0xDD → **NMI**: PC −= 1 (возврат на перевыбираемый опкод), push PC, IFF2 := IFF1, IFF1 := 0, PC := 0x0066,
   **независимо от IFF1**.
6. Иначе IFF1 = 0 → запрос **выбрасывается** (0xE1B8 → снова 0xE012, в конце GPIOR0 = GPIOR1 = 0).
   Защёлки «до EI» нет.
7. Иначе: PC −= 1, push PC, [0x09A9] := IFF1, [0x09AA] := IFF2, IFF1 = IFF2 = 0, и по IM:
   - IM 2: PC := слово (I·256 + V) (младший байт первым);
   - IM 1: PC := 0x0038;
   - IM 0 и IM «3» (ED 4E/6E): V исполняется как однобайтный опкод основной таблицы (0xE292 `jmp 0x410`).
     PC уже в стеке, поэтому `RST n` положит его **второй раз** — ошибка прошивки.
8. RETI = RETN (0x7600, 0x76D6): IFF1 := IFF2, pop PC, затем 0xE000: **IFF1/IFF2 := [0x09A9]/[0x09AA]**
   (значения на момент приёма последнего маскируемого прерывания) и сразу проверка новых запросов.
9. EI (0x2EC4) ставит IFF1 = IFF2 = 1 **без задержки на одну команду**: прерывание может прийти перед командой после EI.
10. HALT (0x1322): PC −= 1, т.е. HALT повторяется. Прерывание кладёт в стек адрес **самого HALT**, после RETI
    процессор снова в HALT. Программы с `EI; HALT` как «ждать одно прерывание» зависнут [код; на реальном Z80 в стек идёт HALT+1].
11. Таймер 10 мс AVR (TIMER2 COMPA 0x008C) только увеличивает TMR_10MS [0x3F56]; своего прерывания Z80 у него нет.
    По умолчанию INT_MASK = 0 → Z80 прерываний не получает вообще.

## 7. Совместимость, скорость

### 7.1 Недокументированные команды [код]

| Что | Поведение 4.67 |
|---|---|
| IXh/IXl/IYh/IYl (DD/FD 24, 25, 26, 2C.., 44.., 60..6F, 84.. и т.д.) | реализованы (напр. DD 44 0x5242 `mov r10,r8`) |
| DD/FD + обычный опкод (DD 00, DD 01, DD 04 …) | исполняется как без префикса |
| DD DD, DD ED, DD FD, FD DD, FD ED, FD FD | NONI: **оба байта съедены как NOP**, следующий байт — новый опкод (на Z80: второй префикс действует) |
| DD CB d xx / FD CB d xx, xx ≠ x6/xE | NONI: 4 байта съедены, ничего не делает (на Z80 — операция + копия в регистр) |
| SLL (CB 30..37) | реализована (0x36F4: сдвиг влево, бит0 := 1) |
| ED 70 IN (C) | NONI |
| ED 71 OUT (C),0 | реализована |
| NEG/RETN/IM дубли | все реализованы; ED 4E/6E → IM 3 = IM 0 |
| ED NONI (28..3F, 80..9F, AC..AF, B4..B7, BC..FF) | 2-байтный NOP |
| флаги X/Y (биты 3, 5 F) | всегда 0 |
| IN r,(C), INI/IND… | порт = только C (B не участвует); IN r,(C) флаги **не меняет** |
| R | таймер, а не счётчик M1 |
| LDIR/LDDR/CPIR/CPDR/INIR/OTIR… | вся серия за одну «команду», без прерываний, PC не возвращается |

Документация: «выполняет zexdoc» (`criss_architecture.txt`) — документированные флаги верны, zexall — нет.

### 7.2 Запись в память и экран [код]

Все 296 мест записи во внешнее ОЗУ (счёт `cbi PORTD,5` = 297, `cp hi,r6` = 296; единственное исключение 0xFE34 —
служебная запись видео, которая шлёт SPI без условия) имеют вставку:

```
out PORTC,hi; out PORTA,lo; out PORTB,data; out DDRB,0xFF
cp  hi, r6          ; r6 = 0xF8
cbi PORTD,5         ; /WE = 0
brcs no_screen
...  SPI к КВУ: три байта hi, lo, data (с паузами), CS через PORTB (cpu-io.md §2.3)
no_screen: out PORTD,0xFF
```

Т.е. запись идёт в ОЗУ **всегда**, и для адресов ≥ 0xF800 дополнительно уходит по SPI. Чтения без ловушек.
Касается и PUSH/CALL/RST/прерываний (стек в F800+ тоже шлётся), LDI/LDIR, BIOS READ в DMA, восстановления снимка.
(Загрузчик образа пишет только < 0xF800.)

### 7.3 Такт и скорость [код + расчёт]

- Тактовая AVR ≈ **20 МГц** [догадка, сходятся два признака]: UBRR1 = 10 для 115200 (20.27 МГц) и TIMER2
  /1024, OCR2A = 0xC0 для 10 мс (19.8 МГц). Фьюзы ЦПУ: внешний генератор (Low 0xE0, `firmware.txt`), КВУ выдаёт
  тактовую на B0 [догадка: общий генератор 20 МГц].
- Выборка 16 тактов; оценка полных времён (скрипт `scratchpad/re_cpu/cyc.py`, без прерываний, запись < F800):

| Команда | Тактов AVR | мкс | Z80 4 МГц, мкс |
|---|---|---|---|
| NOP | 19 | 0.95 | 1.0 |
| LD B,C | 20 | 1.00 | 1.0 |
| LD B,n / LD A,(HL) | 28 | 1.40 | 1.75 |
| LD (HL),A (< F800) | 32 | 1.60 | 1.75 |
| ADD A,B | 22 | 1.10 | 1.0 |
| INC HL / ADD HL,BC | 21 / 25 | 1.05 / 1.25 | 1.5 / 2.75 |
| JP nn | 40 | 2.0 | 2.5 |
| CALL nn | 64 | 3.2 | 4.25 |
| RET / PUSH BC / POP BC | 42 / 43 / 39 | ~2.0 | 2.5 / 2.75 / 2.5 |
| LD HL,(nn) | 53 | 2.65 | 4.0 |
| запись в F800+ | +~110 | +5.5 | — |

Итого примерно Z80 на 4–5 МГц, экранные записи заметно медленнее. Плюс ISR AVR (UART, таймер) и SPI-обмен.

### 7.4 Замедление «CPU SPEED» [код]

Консоль H, A..F → [0x09AB] = 0, 1, 4, 6, 8, 10 (0x18B00: `r21 = буква−'A'`, при r21 ≠ 1 удваивается).
Таблицы пересобираются (0x1114C), при r21 ≠ 0 все 256 входов основной таблицы уменьшаются на 2 слова (0x18B22) →
каждый опкод сначала проходит `jmp 0x418`: `adiw Z,2; lds r21,[0x09AB]; если бит1 = 1 → сразу ijmp; иначе r21 раз
(dec + 4 nop + brne = 7 тактов)`. Из-за проверки бита 1 значения 6 и 10 (45 % и 15 %) **паузы не дают**
(только ~10 тактов пролога) — ошибка или намеренно, неизвестно. Для FPGA: достаточно режима «полная скорость» +
по желанию делитель.

База 0x3F00 подтверждена: банк F6/F7 → 0x3F00, длина 254 (0x1018E, 0x1022E). Использование в моей части:

| Смещ. | SRAM | Имя (док.) | Что делает прошивка |

| 0 | 0x3F00 | HW_FLAG | номер платформы (таблица 0x16A10) |
| 1 | 0x3F01 | CON_IOBYTE | IOBYTE прошивки, по умолч. 0x11 |

| 22–24 | 0x3F16..18 | CON_LAST_CHAR / MODK / KACT | CONIN |
| 25 | 0x3F19 | LST_LAST_CHAR | LISTST |

## Открытые вопросы

1. FL32 2/3: что 0x17C70 = умножение, а 0x17E64 = деление — вывод по структуре кода `fp-bit`; не проверено запуском.
   Нужен тест на железе или прогон в эмуляторе AVR (simavr).
2. Тактовая AVR 20 МГц — по UART/таймеру, не по схеме. Посмотреть кварц на `schematic9.png`.
3. Формат дескриптора (кроме имени): что пишет r1715sd.exe (размер?) — прошивке не нужно, но нужно для утилит.
4. Ошибка MUL: есть ли программы, которые полагаются на ED 77 (Turbo Pascal / библиотеки КРИСС)? Если нет —
   можно делать правильное умножение; если да — повторить ошибку.
5. HALT после прерывания возвращается в HALT; IM 0 + RST двойной push; потеря прерываний при DI. Повторять ли
   эти особенности в ядре или делать как настоящий Z80? Образы SCPX используют IM 2 — надо посмотреть, есть ли
   у них HALT в ожидании.
6. Чем Z80 может писать в SRAM AVR (порт FF 33/34 — по `cpu-io.md` только адреса 0..0xFF, т.е. регистры/I/O AVR)?
   Если есть программы, которые лезут в регистры AVR (r0..r31 = регистры Z80!), их поддержка в FPGA потребует
   отображения этих адресов на регистры ядра.
7. Значения по умолчанию векторов прерываний (ОЗУ DS1305 0x5F..0x6E) неизвестны — нужен дамп ОЗУ RTC с живой машины.
8. Нестандартные коды замедления 6 и 10 (без паузы) — ошибка или так задумано.
9. Внутренние BIOS FA/FB/FC/FF — назначение по экрану (если понадобится) уточнить вместе с `cpu-io.md` §12.
