# План ядра КРИСС CP/M для Karabas Go / Mini / Mini G

Цель: компьютер [КРИСС CP/M](https://criss.radio.ru/) (И. С. Решетников, журнал «Радио» 2021–2023) на платах Karabas (XC6SLX25, ISE 14.7). У оригинала нет HDL: Z80 программно эмулирует ATmega1284P, периферию и видео ведут ещё три AVR. Ядро пишем своё, поведение берём из документации сайта и из дизассемблера прошивок.

## Решения пользователя (2026-11-20)

- Начинаем. Репозиторий `karabas-go-core-criss` пока **локальный**, публичным станет к первому выпуску.
- В `.kg` кладём ПЗУ (загрузочный образ CP/M, знакогенераторы); образы дискет `.cpm` — внешние файлы на SD.
- Автору **не пишем**. Карту портов и недокументированные функции ищем дизассемблером прошивок.

Решения после дизассемблера (2026-11-20):

- Z80 ведёт себя как настоящий (T80: прерывания, EI, HALT, флаги X/Y); явные ошибки 4.67 исправляем (MUL `ED 77`, FF 39, ESC g); видимое поведение консоли (неизвестная ESC съедает 5 байт, прокрутка при символе в правом нижнем углу и т. п.) — как в оригинале.
- Режимы 64 столбца показывают все 64 (у оригинала 61).
- Снимки ОЗУ 25LC1024 (загрузка A / B, Ctrl+Alt+F1 / F2) — в Ф3, снимки файлом на SD.
- Системная консоль Ctrl+Alt+Del → OSD: образы A–D, платформа, скорость, IOBYTE; векторы прерываний и прочие настройки (96 байт ОЗУ DS1305) — значения по умолчанию, хранение файлом на SD.

Прошивки, страницы сайта и схема лицензии не имеют: они в `upstream/` (вне git, `.gitignore`), их скачивает `tools/fetch_upstream.sh` с проверкой sha256. В git попадает только то, что нужно для сборки; что именно из прошивок войдёт в `.kg` (шрифты, загрузочный образ) — решаем перед публикацией.

## Оригинал (что уже известно)

| Узел | Оригинал | Источник |
|---|---|---|
| ЦПУ | ATmega1284P, эмулятор Z80 (~4 МГц, проходит zexdoc), ОЗУ W24512 64 КБ | сайт, BOM |
| BIOS | ловушки `ED 00`–`ED 26` = функции BIOS 0–38, `ED 27` = BDOS, `ED 77` MUL, `ED 7F` DIV, `ED A4`–`A7` FL32 0–3 | таблица опкодов справочника, `CPM22.Z80` |
| КВУ | ATmega328P 20 МГц (все МК на 20 МГц): PS/2 клавиатура и мышь, звук (одноголосый), GPIO PCF8574 по I2C, RS-232 | сайт |
| Видео | ATmega328P + ATtiny13, генератор 25,175 МГц (VGA 640×480), текст 80×25 / 24×80 / 30–31×64, псевдографика 160×96; версия 6.x: ATtiny84 + 74HC173, 8 цветов | сайт, BOM |
| Часы | DS1305 (SPI) | BOM |
| Сеть | ENC28J60 | BOM |
| ПЗУ | 25LC1024 (SPI EEPROM 128 КБ), только в варианте «Максимальная»: два снимка ОЗУ 64 КБ + состояние ЦПУ (загрузка A / B, переключение задач Ctrl+Alt+F1 / F2), не ПЗУ ОС | BOM, `docs/re/cpu-core.md` |
| SD | «сырая» карта без FAT: блок 00 — имя карты, 01–EF — образы дискет, F0–FF — загрузочные образы (снимок ОЗУ, старт с 0x0100) | «Работа с SD-картами» |

Дискета `.cpm`: 819 200 байт, секторы по 128 байт, 80 секторов на дорожку, 80 дорожек, 2 системные дорожки, блок 2 КБ, DSM 389, DRM 127, каталог с 0x5000 (`CPM22.Z80`; у cpmtools это `ris1715`: 40 × 160, boottrk 1).

Загрузочный образ: `CPM22.bin` (63 482 байта, CP/M 2.2 из исходников DR + BIOS на ловушках, TPA 55 КБ, нужна прошивка ЦПУ 4.64+) или `system.bin` (SCPX Robotron 1715, TPA 48 КБ).

Порты Z80 (частично из справочника): D0 VSTAT, D1/D2 курсор, D3 модификаторы, D4 скан-код, D5 символ CP866, D6 + E0–EF звук, D7/D8 I2C / мышь, D9/DA мышь dX/dY, DB–DD системный запрос, DE таймер 10 мс, DF + F1–F3 RS-232, банки F4/F5 видео, F6/F7 системные переменные, FA/FB Ethernet, FC/FD SPI; FE / FF — командные порты внешних и внутренних устройств; 00–CF — совместимость (Robotron 1715 и др.). Запись в F800–FFFF дублируется на экран (Robotron).

## Итоги дизассемблера (Ф0)

Отчёты: `docs/re/cpu-core.md` (регистры, таблицы опкодов, ловушки, диск, загрузка, прерывания), `docs/re/cpu-io.md` (порты, команды FE / FF, SPI, ESC-интерпретатор, сеть), `docs/re/periph.md` (КВУ, ВГА, ATtiny13, CLR, шрифты, клавиатура, звук). Данные — `tools/re/*.py` → `upstream/extract/` (шрифты CP0–CP4, таблицы клавиатуры, тоны, заставка).

- Ловушки: только BIOS 0–16 (BOOT / WBOOT / HOME пустые, CONIN ждёт повтором ловушки, ошибки диска не сообщаются); BIOS 17–38 (`ED 11`–`ED 26`) в 4.67 ничего не делают. `ED 27` BDOS: 6 и 11 сам, остальное — переход на 0xCABF (только образ SCPX). MUL (`ED 77`, с ошибкой), DIV (`ED 7F`), FL32 (`ED A4`–`A7`: IEEE single (HL) op (BC) → (HL)).
- Диск: блок SD = база·4096 + дорожка·20 + сектор/4; загрузочный образ = 124 блока в 0x0000–0xF7FF, старт PC = SP = 0x0100; WBOOT ничего не читает.
- Экран — ОЗУ Z80 с F800 (y·CHARS + x), каждая запись ≥ F800 уходит в КВУ, видео берёт копию; курсор = символ 0 в позиции курсора, мигание 0,5 с.
- Видео 640×480@60 (800×525, синхро отрицательные), знак 8 точек, высота строки 20 / 19 / 16 / 15 для 24 / 25 / 30 / 31 строк; 64-столбцовые режимы реально показывают 61; кодовая страница 7 = своя страница на каждую строку (байты с FF80); цвет — цвет символа на знакоместо, только 24×80.
- Порты D0–F3 — регистры КВУ (клавиатура, таймер 10 мс, звук, RS-232 9600, мышь, I2C, SYSRQ, регистр событий F0); 00–CF — только Robotron 1715 (IN 0C клавиатура, OUT 18 / 19 = 8275); F4–FD — банки адрес / данные; FE — команды (SPI, SD, CAN 16–47, сеть 48–72, часы 80–87); FF — FL32, доступ к памяти AVR, версия, UART1.
- Прерывания: 16 источников, маска INT_MASK (по умолчанию всё выключено), вектор из ОЗУ DS1305.

## Архитектура ядра (предложение, проверяется в Ф0)

- Z80 = T80 из соседних ядер, ~4 МГц (турбо — пункт OSD).
- Ловушки `ED xx`: T80 останавливается, вспомогательный процессор читает регистры (выход `REG`), выполняет функцию и пишет их обратно (`DIRSet` / `DIR` у T80 уже есть).
- Вспомогательный процессор: VexRiscv с программой на C (как VDP в core-agon, Doom): BIOS, ESC-терминал, порты D0–FF, системные переменные, диски.
- ОЗУ Z80 64 КБ: SRAM платы; вспомогательный процессор пишет в неё сам, пока Z80 стоит (DMA диска, загрузка образа).
- Видео: текстовый буфер и цвета в BRAM, знакогенераторы CP0–CP4 из прошивки ВГА, псевдографика 160×96 = символы 2×4, вывод 640×480 на HDMI / VGA.
- Дискеты: файлы `.cpm` на SD (A: / B:, выбор в OSD), слоты `kg_l2_img` как в pdp2026; загрузочный образ — из `.kg`.
- Клавиатура USB → коды PS/2 → таблицы КВУ (CP866, РУС/ЛАТ по ScrollLock).
- Звук: тон КВУ; часы — время платы (`kg_mcu_rtc`); RS-232 — USB-последовательный порт платы.

## Фазы

### Ф0 — исследование и замер (ветка f0-survey)

1. Дизассемблер прошивок (нужен `binutils-avr`):
   - ЦПУ 4.67 (`avr:51`): таблица опкодов, подтаблица `ED` (полный список ловушек, функции BIOS 17–38), обработчики `IN` / `OUT` (все порты, команды FE / FF), загрузка с SD, системные переменные, ESC-интерпретатор; сверка с 4.66.
   - КВУ 0.24: регистры D3–DF, таблицы раскладок, мелодии.
   - ВГА 1.24 и шрифты 2023-11: знакогенераторы, размер знакоместа, тайминги, режимы 64 столбца, протокол ЦПУ → ВГА; CLR 0.5 — цвет.
   - Итог — таблица портов и функций в этом файле.
2. Эталон: если найдётся способ запустить оригинальные прошивки (simavr), снимать трассы с него; иначе — проверка по документации и программам.
3. Замер XST: T80 + VexRiscv + текстовое видео + SD-слоты на Mini G (LUT, RAMB16, частота).

### Ф1 — Mini G: загрузка CP/M (ветка f1-minig)

T80 + ловушки BIOS, загрузочный образ из `.kg`, диск A: из файла, текстовый экран 80×25 с базовыми управляющими кодами, клавиатура. Цель: приглашение `A>`, `DIR`, запуск программ с образа CRISS1.

### Ф2 — терминал полностью

ESC-команды КРИСС, режимы 24 / 25 / 30 / 31 строк, знакогенераторы, окна, строка статуса, псевдографика 160×96, 8 цветов (6.x).

### Ф3 — периферия

Таймер, часы, звук, мышь, RS-232, системные переменные, снимки ОЗУ (файл на SD, загрузка A / B, Ctrl+Alt+F1 / F2); совместимость Robotron 1715 / Kaypro (порты 00–CF, кодировки).

### Ф4 — сеть через ESP8266

Решение пользователя (2026-11-20): вместо ENC28J60 — ESP8266 платы, прошивка ESP **заводская AT** (не перешиваем). Эмулируем сетевой API КРИСС (порт FE, команды 48–71, банк FA/FB, PUNCH/READER по сети в системной переменной 74), а не сам ENC28J60:

- UDP отправка / приём → `AT+CIPSTART="UDP"` (несколько сокетов через `CIPMUX`), PING → `AT+PING`, свой IP — от ESP (DHCP), `LAN_IP_MY` от Z80 игнорируется.
- Сырые кадры и регистры ENC28J60: вспомогательный процессор разбирает исходящий кадр (UDP → ESP, ICMP echo → PING, ARP — отвечает сам поддельным MAC шлюза) и собирает входящие кадры Ethernet / IP / UDP с контрольными суммами; регистры возвращают правдоподобные значения (связь есть, счётчики).
- Не поддерживаются: не-IP кадры, сырой TCP (у КРИСС TCP нет), доступ снаружи NAT.

Точные входы / выходы команд — из дизассемблера (Ф0, `docs/re/cpu-io.md`, раздел «Сеть»).
