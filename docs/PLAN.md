# План ядра КРИСС CP/M для Karabas Go / Mini / Mini G

Цель: компьютер [КРИСС CP/M](https://criss.radio.ru/) (И. С. Решетников, журнал «Радио» 2021–2023) на платах Karabas (XC6SLX25, ISE 14.7). У оригинала нет HDL: Z80 программно эмулирует ATmega1284P, периферию и видео ведут ещё три AVR. Ядро пишем своё, поведение берём из документации сайта и из дизассемблера прошивок.

## Решения пользователя (2026-11-20)

- Начинаем. Репозиторий `karabas-go-core-criss` пока **локальный**, публичным станет к первому выпуску.
- В `.kg` кладём ПЗУ (загрузочный образ CP/M, знакогенераторы); образы дискет `.cpm` — внешние файлы на SD.
- Автору **не пишем**. Карту портов и недокументированные функции ищем дизассемблером прошивок.

Решения после дизассемблера (2026-11-20):

- Z80 ведёт себя как настоящий (T80: прерывания, EI, HALT, флаги X/Y); явные ошибки 4.67 исправляем (MUL `ED 77`, FF 39, ESC g); видимое поведение консоли (неизвестная ESC съедает 5 байт, прокрутка при символе в правом нижнем углу и т. п.) — как в оригинале.
- Режимы 64 столбца показывают все 64 (у оригинала 61).
- Снимки ОЗУ 25LC1024 (загрузка A / B, Ctrl+Alt+F1 / F2) — в Ф3, снимки файлом на SD.
- Системная консоль Ctrl+Alt+Del → OSD: образы A–D, платформа, скорость, IOBYTE; векторы прерываний и прочие настройки (96 байт ОЗУ DS1305) — значения по умолчанию, хранение файлом на SD.

Прошивки, страницы сайта и схема лицензии не имеют. Решение пользователя (2026-11-20): проект открытый, их можно класть в репозиторий; в README — ссылка на сайт, авторы, «лицензия неизвестна». `upstream/` — скачанное (`tools/fetch_upstream.sh`, sha256), в git; вне git только производное (`upstream/fw/x`, `dis`, `extract`). ПЗУ данных и `.kg` коммитятся, как в других ядрах.

| КВУ | ATmega328P 20 МГц (все МК на 20 МГц): PS/2 клавиатура и мышь, звук (одноголосый), GPIO PCF8574 по I2C, RS-232 | сайт |
| Видео | ATmega328P + ATtiny13, генератор 25,175 МГц (VGA 640×480), текст 80×25 / 24×80 / 30–31×64, псевдографика 160×96; версия 6.x: ATtiny84 + 74HC173, 8 цветов | сайт, BOM |
| Часы | DS1305 (SPI) | BOM |
| Сеть | ENC28J60 | BOM |

Дискета `.cpm`: 819 200 байт, секторы по 128 байт, 80 секторов на дорожку, 80 дорожек, 2 системные дорожки, блок 2 КБ, DSM 389, DRM 127, каталог с 0x5000 (`CPM22.Z80`; у cpmtools это `ris1715`: 40 × 160, boottrk 1).

Загрузочный образ: `CPM22.bin` (63 482 байта, CP/M 2.2 из исходников DR + BIOS на ловушках, TPA 55 КБ, нужна прошивка ЦПУ 4.64+) или `system.bin` (SCPX Robotron 1715, TPA 48 КБ).

Порты Z80 (частично из справочника): D0 VSTAT, D1/D2 курсор, D3 модификаторы, D4 скан-код, D5 символ CP866, D6 + E0–EF звук, D7/D8 I2C / мышь, D9/DA мышь dX/dY, DB–DD системный запрос, DE таймер 10 мс, DF + F1–F3 RS-232, банки F4/F5 видео, F6/F7 системные переменные, FA/FB Ethernet, FC/FD SPI; FE / FF — командные порты внешних и внутренних устройств; 00–CF — совместимость (Robotron 1715 и др.). Запись в F800–FFFF дублируется на экран (Robotron).

## Итоги дизассемблера (Ф0)

Отчёты: `docs/re/cpu-core.md` (регистры, таблицы опкодов, ловушки, диск, загрузка, прерывания), `docs/re/cpu-io.md` (порты, команды FE / FF, SPI, ESC-интерпретатор, сеть), `docs/re/periph.md` (КВУ, ВГА, ATtiny13, CLR, шрифты, клавиатура, звук). Данные — `tools/re/*.py` → `upstream/extract/` (шрифты CP0–CP4, таблицы клавиатуры, тоны, заставка).

- Ловушки: только BIOS 0–16 (BOOT / WBOOT / HOME пустые, CONIN ждёт повтором ловушки, ошибки диска не сообщаются); BIOS 17–38 (`ED 11`–`ED 26`) в 4.67 ничего не делают. `ED 27` BDOS: 6 и 11 сам, остальное — переход на 0xCABF (только образ SCPX). MUL (`ED 77`, с ошибкой), DIV (`ED 7F`), FL32 (`ED A4`–`A7`: IEEE single (HL) op (BC) → (HL)).
- Диск: блок SD = база·4096 + дорожка·20 + сектор/4; загрузочный образ = 124 блока в 0x0000–0xF7FF, старт PC = SP = 0x0100; WBOOT ничего не читает.
- Экран — ОЗУ Z80 с F800 (y·CHARS + x), каждая запись ≥ F800 уходит в КВУ, видео берёт копию; курсор = символ 0 в позиции курсора, мигание 0,5 с.
- Видео 640×480@60 (800×525, синхро отрицательные), знак 8 точек, высота строки 20 / 19 / 16 / 15 для 24 / 25 / 30 / 31 строк; 64-столбцовые режимы реально показывают 61; кодовая страница 7 = своя страница на каждую строку (байты с FF80); цвет — цвет символа на знакоместо, только 24×80.
- Порты D0–F3 — регистры КВУ (клавиатура, таймер 10 мс, звук, RS-232 9600, мышь, I2C, SYSRQ, регистр событий F0); 00–CF — только Robotron 1715 (IN 0C клавиатура, OUT 18 / 19 = 8275); F4–FD — банки адрес / данные; FE — команды (SPI, SD, CAN 16–47, сеть 48–72, часы 80–87); FF — FL32, доступ к памяти AVR, версия, UART1.
- Прерывания: 16 источников, маска INT_MASK (по умолчанию всё выключено), вектор из ОЗУ DS1305.

## Архитектура ядра

- Z80 = T80 из соседних ядер, ~4 МГц (турбо — пункт OSD).
- Ловушки `ED xx`: T80 останавливается, вспомогательный процессор читает регистры (выход `REG`), выполняет функцию и пишет их обратно (`DIRSet` / `DIR` у T80 уже есть).
- Вспомогательный процессор: VexRiscv с программой на C (как VDP в core-agon, Doom): BIOS, ESC-терминал, порты D0–FF, системные переменные, диски.
- ОЗУ Z80 64 КБ — SRAM платы; код и данные помощника — SDRAM (кэши 4K / 4K, как core-doom); помощник пишет в ОЗУ Z80 сам (DMA диска, загрузка образа), пока Z80 стоит.
- Видео: копия экрана (записи Z80 в F800–FFCF) и цвета в BRAM, знакогенераторы CP0–CP4 из прошивки ВГА (в `.kg`), псевдографика 160×96 = символы 2×4 CP1 / CP4, 640×480@60, высота строки 20 / 19 / 16 / 15; курсор = символ 0 с миганием 0,5 с.
- Дискеты: файлы `.cpm` на SD (A: / B:, выбор в OSD), слоты `kg_l2_img` как в pdp2026; загрузочный образ — из `.kg`.
- Клавиатура USB → коды PS/2 → таблицы КВУ (CP866, РУС/ЛАТ по ScrollLock).
- Звук: тон КВУ; часы — время платы (`kg_mcu_rtc`); RS-232 — USB-последовательный порт платы.

### Ф1 — Mini G: загрузка CP/M (ветка f1-minig) — ГОТОВО 2026-11-20 (OSD одобрен пользователем)

T80 + ловушки BIOS, загрузочный образ из `.kg`, диск A: из файла, текстовый экран 80×25 с базовыми управляющими кодами, клавиатура. Цель: приглашение `A>`, `DIR`, запуск программ с образа CRISS1.

Устройство (как SoC core-doom): программа помощника и его данные — в SDRAM (загрузчик `.kg` kind 0, без изменений), в SRAM — только ОЗУ Z80 64 КБ. Помощник обращается к SRAM лишь пока Z80 стоит (ловушка, сброс), поэтому арбитра нет. Окно ОЗУ Z80 у помощника — в некэшируемой области VexRiscv (бит 31 адреса): Z80 меняет память между ловушками. Шрифты из `.kg` помощник копирует в BRAM видео, образ CP/M — в SRAM. Клавиатура — скан-коды PS/2 от `kg_mcu2` (как в core-agon), таблицы КВУ индексируются ими.

Ловушка: детектор префиксов по циклам M1 (`ED ED 02` — не ловушка), `ED 00`–`27`, `77`, `7F`, `A4`–`A7` (у T80 это NOP), затем WAIT на T2 следующего M1, INT / NMI закрыты до отпускания; помощник читает `REG`, пишет `DIR` + `DIRSet`, отпускает WAIT. Загрузка идёт тем же путём (PC = SP = 0x0100).

Шаги:
1. `criss_z80.v` (T80s + `REG` / `DIR`) и узел ловушек; тест Verilator: `REG` → `DIR` без изменений после `EXX` / `EX AF,AF'`, ловушки и не-ловушки, запись PC из остановки.
2. Программа помощника на C + её сборка для ПК: заглушка MMIO + интерпретатор Z80 с теми же ловушками; загрузка `CPM22.bin` и образа `.cpm` до `A>` и `DIR` за секунды, снимок экрана текстом.
3. SoC (`criss_soc.v`: VexRiscv, SDRAM, SRAM, MMIO, сектора SD нескольких слотов, видео, клавиатура) и короткий тест; полную загрузку в RTL-симуляции — только с согласия пользователя.
4. Верх Mini G, `core.json` (образы дискет A: / B: — пункты OSD как в rc2014 / pdp2026), сборка, проверка на плате.

Ход (2026-11-20):
- 1 готово: `sim/z80trap/run.sh` — PASS (4 тыс. тактов).
- 2 готово: `fw/host/test.sh` — CP/M с CRISS1.cpm: `DIR`, `SAVE`, ZORK1 (доли секунды).
- 3 готово: `sim/soc/run.sh` — RTL до `a>` за 167 мс модельного времени (Z80 4,17 МГц), `DIR` с клавиатуры PS/2, `SAVE` пишет образ; `sim/video/run.sh` — кадр 640×480 с экраном `DIR` (PNG).

- 4: сборка Mini G 26112001 — 7 107 LUT (47 %), 71 % слайсов, 21 RAMB16 + 9 RAMB8, тайминги выполнены. **Плата Mini G: работает** — CP/M с /criss/CRISS1.cpm, `DIR`, ZORK1 (`docs/f1-zork-minig.jpg`). USB CDC платы сбрасывается раз в 2–10 с (известная беда платы с ядрами на SDRAM, как archie / UKNC; решено чинить в железе). Код F12 (сброс OSD) попадал в CP/M после перезапуска: прошивка чистит очередь PS/2 при загрузке.

### Ф3 — периферия (ветка f3-periph) — ГОТОВО

Таймер, часы, звук, мышь, RS-232, системные переменные, снимки ОЗУ (файл на SD, загрузка A / B, Ctrl+Alt+F1 / F2); совместимость Robotron 1715 / Kaypro (порты 00–CF, кодировки).

Устройство: каждый цикл IN / OUT Z80 (не подтверждение прерывания) останавливает Z80 через WAIT, как ловушка ED; помощник берёт порт, направление, данные из MMIO, для IN кладёт байт, отпускает. Все порты — на C по `docs/re/cpu-io.md` / `periph.md` (регистры КВУ D0–F3 моделирует помощник). Прерывание Z80: уровень и байт вектора задаёт помощник, цикл подтверждения отдаёт вектор аппаратно и снимает запрос.

Шаги (одна ветка, коммиты по шагам):
1. Ловушка IN / OUT в RTL + диспетчер портов в прошивке: регистры КВУ (клавиатура D3–D5, D0–D2, таймер DE, события F0, SYSRQ DB–DD), банки F4–FD (системные переменные F6 / F7 — из состояния прошивки), FE 1 / FF (FL32, версия), прерывания (INT_MASK, источники КВУ).
2. Звук: проигрыватель мелодий КВУ (D6, E0–EF, ESC m, таблица тонов) + тон в RTL; BELL.
3. RS-232 (F1–F3, DF, скорость через SYSRQ) — USB-последовательный порт платы (kg_mcu2 PORT 0, как core-rc2014); UART1 (FF 37–39) — туда же или беклог.
4. Мышь (D7–DA, kg_mcu2 MS_*); I2C GPIO — ответ «ошибка» (на платах нет PCF8574).
5. Часы FE 80–87 (время платы), 96 байт ОЗУ DS1305 и снимки ОЗУ 25LC1024 — файл backup RAM на SD (как core-doom), Ctrl+Alt+F1 / F2, загрузка снимка.
6. Платформы Robotron 1715 RU / EN, Kaypro, TRS-80, VT100 (вывод, ввод, IN 0C, OUT 18 / 19) — пункт OSD «Platform».

Ход (2026-11-20): шаги 1–5 сделаны. Тесты на ПК: `sim/tests/run.sh` (t1–t5 + снимки), t5 и на RTL SoC. Плата Mini G 26112004: t5 (версия, системные переменные, FPU, таймер, прерывание IM 1, часы платы), t6 RS-232 через USB-порт `-if02` в обе стороны, t7 мышь (E0 / E1, D8–DA), t8 мелодия (гамма 260–520 Гц на HDMI-звуке, BEL 2 кГц), снимки ОЗУ Ctrl+Alt+F1 / F2 туда и обратно. Решения по ходу:
- Файл backup RAM прошивки платы создаётся только после загрузки через FL-загрузчик (имя игры), у CRISS его нет → настройки и снимки — в образе NVRAM: пункт OSD F «NVRAM» (слот 4, `/criss/criss.nvr`, 261 сектор, `make nvr`; без образа F1 / F2 ничего не делают).
- RS-232 = порт 0 `kg_mcu2` (`ENABLE_PORTS`), UART1 (FF 37–39) — в беклог (на платах нет второй линии); I2C GPIO — «ошибка» (PCF8574 нет).
- Скорость RS-232 (SYSRQ C4) принимается и игнорируется (USB).

Шаг 6 (2026-11-20): платформы по `docs/re/cpu-io.md` 3 / 12.3 / 12.4 (`fw/con.c`, таблицы прошивки в ПЗУ данных: IN 0C, КОИ-7, VT, записи платформ); OSD Platform (index 4) и Boot (index 5: CP/M / снимок 1 / снимок 2). Тест t9 (позиция текста способом платформы) на ПК для CRISS / Robotron RU / Kaypro / VT100; плата Mini G 26112005 (7 724 LUT, 76 % слайсов): VT100 и Robotron RU как на ПК, кадр OSD `docs/f3-osd-minig.jpg` одобрен пользователем, влито в master 2026-11-20.

### Ф4 — сеть через ESP8266

Решение пользователя (2026-11-20): вместо ENC28J60 — ESP8266 платы, прошивка ESP **заводская AT** (не перешиваем). Эмулируем сетевой API КРИСС (порт FE, команды 48–71, банк FA/FB, PUNCH/READER по сети в системной переменной 74), а не сам ENC28J60:

- UDP отправка / приём → `AT+CIPSTART="UDP"` (несколько сокетов через `CIPMUX`), PING → `AT+PING`, свой IP — от ESP (DHCP), `LAN_IP_MY` от Z80 игнорируется.
- Сырые кадры и регистры ENC28J60: вспомогательный процессор разбирает исходящий кадр (UDP → ESP, ICMP echo → PING, ARP — отвечает сам поддельным MAC шлюза) и собирает входящие кадры Ethernet / IP / UDP с контрольными суммами; регистры возвращают правдоподобные значения (связь есть, счётчики).
- Не поддерживаются: не-IP кадры, сырой TCP (у КРИСС TCP нет), доступ снаружи NAT.

Точные входы / выходы команд — из дизассемблера (Ф0, `docs/re/cpu-io.md`, раздел «Сеть»).

ESP на плате (проба 2026-11-20 через `AT+KARABAS=esp` boot-ядра): AT 1.7.6 (SDK 3.0.6), `+UART_CUR:115273,8,1,0,2` (CTS включён), STA, Wi-Fi подключён настройкой прошивки платы (IP по DHCP). `AT+CIPMUX=1` + `AT+CIPDINFO=1`: приём `+IPD,<n>,<len>,<ip>,<port>:<данные>`; `AT+CIPSTART=<n>,"UDP","0.0.0.0",0,<свой порт>,2` — слушать всех; `AT+CIPSEND=<n>,<len>,"<ip>",<port>` → `>` → данные → `SEND OK`; `AT+PING="ip"` → `+<мс>` / `+timeout`. При переходе в мост ESP перезагрузилась (мусор загрузчика 74880, `ready`, `WIFI GOT IP`) — разборщик это переживает. Только команды без записи во флеш ESP (без `_DEF`, `SAVETRANSLINK`): ESP общая для всех ядер.

Шаги (одна ветка f4-net):
1. RTL: UART к ESP (115200 8N1, приёмный буфер 2 КБ, CTS к ESP при > 1792 байт), MMIO 0x70 / 0x74; HAL `hal_esp_get / put`.
2. Прошивка `fw/esp.c`: AT-движок без блокировок — один потоковый разборщик (строки, `+IPD` с данными посреди ожидания `>` / `SEND OK`), очередь команд с тайм-аутами, запуск (AT до ответа, `ATE0`, закрыть все соединения, CIPMUX / CIPDINFO, CIFSR), до 4 UDP-соединений по своему порту (LRU), очередь принятых датаграмм.
3. `fw/net.c`: банк FA / FB, буфер кадра 768 байт, команды FE 48–72 по `cpu-io.md` 11: сборка кадров честно (50 / 51 / 59 / 60 / 61 / 63 / 67 / 68 / 70 / 71); 54 разбирает кадр: UDP → CIPSEND, ARP-запрос → поддельный ответ в очередь (MAC = 02:00:IP), ICMP echo → AT+PING → echo reply в очередь; TCP (72) и не-IP — отбрасываются; 55 / 56 / 66 — синтез принятых кадров (MAC / IP назначения = MAC_MY / IP_MY банка), классификация 11.5. IP_MY / MAC_MY банка — от ESP при запуске. HW_FOUND бит 5 — когда ESP ответила.
4. BIOS по IOBYTE (11.7, 0xE5B4 / 0xE644 / 0xE660 / 0xE67C): CONOUT — каждый бит отдельно (бит 0 экран, бит 2 LAN), LIST / PUNCH по LAN, CONST / CONIN / READER — ввод из сети (FIFO по 32 байта; READER не ждёт: 0 при пустом). Ограничение 4.67 «≤ 22 байт из датаграммы» не повторяем (кадр урезался до 64 байт).
5. Адреса серверов (консоль, принтер, PUNCH / READER) — в образе NVRAM (настройки 0x16–0x2D, 0x55); системной консоли нет → `tools/nvrset.py` правит `.nvr` на ПК.
6. Тесты на ПК: в `host` — поддельная ESP поверх настоящих UDP-сокетов localhost; t11 (UDP эхо, ping, сырые 54 / 55, консоль по сети). Плата: обмен с ПК по Wi-Fi.
