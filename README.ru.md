# Ядро КРИСС CP/M для Karabas Go / Mini / Mini G

[English version](README.md)

Ядро [КРИСС CP/M](https://criss.radio.ru/) (CRISS CP/M) для плат семейства Karabas Go (Xilinx Spartan-6 XC6SLX25). КРИСС CP/M — самодельный компьютер И. С. Решетникова, опубликованный в журнале «Радио» в 2021–2024 годах: машина CP/M 2.2 на Z80 с текстовым экраном на 80 колонок, 8 цветами, звуком, часами и образами дискет на SD-карте. В оригинале микросхемы Z80 нет: его эмулирует ATmega1284P, а клавиатурой, звуком и VGA занимаются другие микроконтроллеры AVR. Это ядро написано с нуля: в нём настоящий Z80 (T80) и небольшой процессор RISC-V, который делает работу прошивок AVR.

| Плата | Видео | Звук | Сеть |
|---|---|---|---|
| Karabas Go | VGA | I2S ЦАП (PCM5102) | ESP8266 платы |
| Karabas Mini | HDMI | HDMI, аналоговый выход (сигма-дельта) | ESP8266 платы |
| Karabas Mini G | HDMI | HDMI, I2S ЦАП | ESP8266 платы |

Файл ядра `src/criss.kg` — один на все три платы.

Состояние: проверено на Mini G (CP/M, программы, консоль, порты, платформы, снимки, сеть). Сборки для Go и Mini на плате ещё не запускались.

## Начало работы

1. Скопируйте `src/criss.kg` в корень SD-карты.
2. Создайте на карте каталог `/criss` и положите туда образы дискет (`.cpm`). Для начала подойдут образы с сайта КРИСС: [CRISS1.cpm](https://criss.radio.ru/criss/img/CRISS1.cpm) (системный диск сайта: утилиты, игры вроде Zork), [CRISS2.cpm](https://criss.radio.ru/criss/img/CRISS2.cpm), [tm2.cpm](https://criss.radio.ru/criss/img/tm2.cpm), [G1715.cpm](https://criss.radio.ru/criss/img/G1715.cpm). Ещё программы — на [странице ПО](https://criss.radio.ru/?soft).
3. Для настроек, снимков ОЗУ и сети нужен ещё образ NVRAM в `/criss`. Пустой делается командой `make nvr` (получится `src/roms/kg/criss.nvr`) или `python3 src/tools/nvrset.py criss.nvr --new`; скопируйте его в `/criss/criss.nvr`.
4. Выберите CRISS CP/M в меню ядер. Откройте OSD (**Menu+Esc**), выберите образ диска A (**Menu+F1**) и образ NVRAM — ядро их запомнит. CP/M стартует сразу: `a>`. Сама CP/M находится в ядре (это загрузочный образ КРИСС), дискета нужна только для программ.

«Menu» — клавиша Windows на клавиатуре.

## Меню OSD

| Пункт | Значения | Клавиши |
|---|---|---|
| Disk A | образ `.cpm` в `/criss` | Menu+F1 |
| Disk B | образ `.cpm` в `/criss` | Menu+F2 |
| NVRAM | образ `.nvr` в `/criss`: настройки (96 байт ОЗУ DS1305) и два снимка ОЗУ по 64 КБ | |
| Platform | CRISS / R1715 RU / R1715 EN / Kaypro / TRS-80 / Kaypro 8b / VT100: каким терминалом работает консоль (см. [Платформы](#платформы)); при смене экран очищается | |
| Boot | CP/M / Snapshot 1 / Snapshot 2: что запускается после сброса | |
| Reset | перезапуск машины | F12 |

Пункт «Setup RTC» в конце меню добавляет прошивка платы: часы КРИСС — это часы платы. Системную консоль оригинала (Ctrl+Alt+Del) заменяют это меню и `nvrset.py`.

## Клавиши

| Клавиши | Действие |
|---|---|
| Menu+Esc | OSD |
| F12, Ctrl+Alt+Shift+Esc | сброс |
| Ctrl+Alt+F1 | сохранить текущую задачу в снимок 1, перейти в снимок 2 |
| Ctrl+Alt+F2 | сохранить текущую задачу в снимок 2, перейти в снимок 1 |
| Scroll Lock | латиница / русская раскладка (как у контроллера клавиатуры КРИСС) |
| Caps Lock | заглавные |
| Num Lock | платформы Robotron: s0 / s1 (латиница / кириллица КОИ-7) |

Клавиатура работает по таблицам контроллера периферии КРИСС (прошивка 0.24): русская раскладка даёт CP866 (КРИСС) или КОИ-7 (Robotron).

Два снимка работают как блоки A / B микросхемы 25LC1024 в КРИСС: можно держать две программы и переключаться между ними. Они хранятся в образе NVRAM; без него Ctrl+Alt+F1 / F2 ничего не делают. Пункт «Boot» запускает снимок вместо CP/M.

## Диски

Образ `.cpm` — дискета КРИСС: 819 200 байт, 80 дорожек по 80 секторов по 128 байт, 2 системные дорожки, блоки по 2 КБ, 128 записей каталога. Это тот же формат, что у образов сайта КРИСС и у Robotron 1715 (cpmtools: diskdef `ris1715`).

Создавать, смотреть и наполнять образы на ПК — `src/tools/cpmimg.py` (Python 3, без пакетов):

```
python3 src/tools/cpmimg.py new my.cpm
python3 src/tools/cpmimg.py add my.cpm GAME.COM README.TXT
python3 src/tools/cpmimg.py ls my.cpm
python3 src/tools/cpmimg.py get my.cpm GAME.COM
```

`cpmtools` (diskdef `ris1715`) и плагин Far с сайта КРИСС тоже открывают эти файлы. Запись из CP/M сразу попадает в файл образа на SD-карте.

Оригинальный КРИСС работает с «сырой» SD-картой без файловой системы (имя карты, до 239 дискет и 16 загрузочных образов в фиксированных блоках). Ядро вместо этого берёт файлы с карты FAT; «сырые» карты КРИСС не поддерживаются.

## Машина

Что есть в ядре от КРИСС (версии прошивок: ЦПУ 4.67, контроллер периферии 0.24, VGA 1.24, модуль цвета 0.5):

- **Процессор:** Z80 на 4,17 МГц, 64 КБ ОЗУ. Все функции BIOS и дополнительные вызовы прошивки КРИСС (ловушки `ED xx`): BIOS CP/M 0–16, короткий вызов BDOS, `MUL`, `DIV`, операции с 32-битными числами с плавающей точкой.
- **Консоль:** полный ESC-терминал КРИСС: режимы 80×24, 80×30, 64×24 и другие, 8 кодовых страниц, окна, строка статуса, точки / линии / окружности, псевдографика 160×96, модуль цвета CLR (8 цветов на знакоместо, статический или по знакоместам).
- **Платформы:** консоль работает и как Robotron 1715 (RU / EN), Kaypro, TRS-80, Kaypro 8 бит и VT100 / ANSI / VT52 (выбор в OSD), с портами 00–CF этих машин (IN 0C, OUT 18 / 19).
- **Порты D0–FF:** регистры контроллера периферии (клавиатура, таймер, события, прерывания), банки F4–FD с системными переменными, команды портов FE / FF (версия, сопроцессор).
- **Прерывания:** IM 1 / IM 2 с векторами и масками КРИСС (события контроллера периферии: клавиатура, таймер, мелодия, RS-232). Линии прерываний сети и часов КРИСС не взводятся.
- **Звук:** звонок (BEL) и проигрыватель мелодий контроллера периферии (ESC m, порт D6).
- **Часы:** DS1305 (FE 80–87) на часах платы; её 96 байт ОЗУ — в образе NVRAM.
- **RS-232:** USB-последовательный порт платы (второй CDC-порт, `-if02`) с управлением потоком. Настройка скорости принимается и игнорируется.
- **Мышь:** USB-мышь платы (порты D7–DA, события).
- **Сеть:** см. [Сеть](#сеть).

Не сделано: второй UART (FF 37–39: на платах нет второй линии), расширитель GPIO по I2C (вызовы отвечают «ошибка»), CAN, слот расширения SPI, загрузка из 25LC1024 без SD-карты.

### Платформы

| Значение OSD | Машина | Шрифт | Вывод | Клавиатура |
|---|---|---|---|---|
| CRISS | КРИСС CP/M | CP866 | все ESC-коды КРИСС | CP866 |
| R1715 RU | Robotron 1715, русский | кодовая страница 2 (КОИ-7) | ESC-коды Robotron, курсор через ESC + 0x7F | латиница заглавными, кириллица (КОИ-7) |
| R1715 EN | Robotron 1715, английский | кодовая страница 3 | ESC-коды Robotron | 7 бит (русские клавиши ничего не дают) |
| Kaypro | Kaypro | CP866, 7 бит | управляющие коды Kaypro | CP866 |
| TRS-80 | TRS-80 | 7 бит | как КРИСС | CP866 |
| Kaypro 8b | Kaypro, 8 бит | CP866 | управляющие коды Kaypro | CP866 |
| VT100 | VT100 / ANSI / VT52 | CP866 | последовательности CSI | CP866 |

Платформы проверены на Mini G для CRISS, VT100 и R1715 RU, на ПК — для Kaypro. R1715 EN, TRS-80 и Kaypro 8b сделаны по прошивке и не проверялись.

## Сеть

В оригинальном КРИСС стоит Ethernet-контроллер ENC28J60 и API на уровне кадров (порт FE, команды 48–79; банк FA / FB). На платах Karabas вместо него Wi-Fi-модуль ESP8266. **Ядро оставляет ESP8266 заводскую AT-прошивку** (1.7.x): модуль не перешивается, и ядро не посылает ему команд, которые пишут во флеш, — модуль общий для всех ядер.

### Настройка

1. Один раз подключите плату к Wi-Fi в boot-ядре: OSD → Setup Wi-Fi. ESP8266 сама держит сеть и получает IP по DHCP.
2. Запустите КРИСС. Ядро находит модуль за секунду-две: взводится бит 5 (LAN) системной переменной HW_FOUND, а в банк FA / FB попадают IP и MAC модуля как `IP_MY` / `MAC_MY`.
3. Для каналов CP/M по сети запишите адреса серверов в образ NVRAM на ПК (в оригинале это делает системная консоль):

```
python3 src/tools/nvrset.py criss.nvr                           # показать
python3 src/tools/nvrset.py criss.nvr con=192.168.1.10:5000     # консольный сервер
python3 src/tools/nvrset.py criss.nvr prn=5001                  # порт сетевого принтера (на консольном сервере)
python3 src/tools/nvrset.py criss.nvr pr=192.168.1.10:5002      # сервер PUNCH / READER
python3 src/tools/nvrset.py criss.nvr lst=0x04                  # LST на сетевой принтер при старте
python3 src/tools/nvrset.py criss.nvr lan=off                   # выключить сеть
```

### Что работает

Ядро даёт Z80 тот же API, что прошивка КРИСС 4.67; программы менять не нужно. Внутри вспомогательный процессор превращает его в AT-команды:

| КРИСС (ENC28J60) | В ядре |
|---|---|
| UDP: собрать и отправить (FE 61, 69, 54) | `AT+CIPSEND` из UDP-соединения нашего порта (`PORT_MY` — порт источника) |
| UDP: приём (FE 55, 66, 67) | датаграммы модуля (`+IPD`) как полные кадры Ethernet / IP / UDP на `MAC_MY` / `IP_MY`, с контрольными суммами |
| ICMP echo request (FE 70 + 54) | `AT+PING`; ответ приходит кадром echo reply (класс 0x8B, `ECHO_CNTR` + 1) |
| ARP-запрос (FE 68 + 54) | отвечает ядро: MAC `02:00:<IP>` (класс 0x82, `MAC_REMOTE`) — ARP модуль делает сам |
| команды кадров (FE 50, 51, 59, 60, 62, 63, 64, 71) | как в 4.67, на буфере кадра 768 байт |
| регистры ENC28J60 (FE 52, 53, 56, 57, 58, 65) | правдоподобные значения: связь есть, `EPKTCNT` = число ждущих кадров, `ESTAT` — готов |
| CON / LST / PUNCH / READER по UDP (IOBYTE) | одна датаграмма на символ к серверу, порт сервера с обеих сторон (как в 4.67) |
| входящий ping, ARP других узлов | отвечает сама ESP8266 |

Каналы CP/M используют биты IOBYTE КРИСС:

| Канал | Переменная | Вывод | Ввод |
|---|---|---|---|
| CON | CON_IOBYTE (системная переменная 1) | бит 2: на консольный сервер (бит 0: экран) | бит 6: с консольного сервера |
| LST | LST IOBYTE (системная переменная 88) | бит 2: на порт сетевого принтера | |
| PUNCH / READER | PR_IOBYTE (системная переменная 72) | бит 2: на сервер PR | бит 6: с сервера PR (READER не ждёт: 0 = ничего) |

Например, `OUT (F6),1 : OUT (F7),55h` отправляет консоль на консольный сервер и берёт с него же клавиши; ПК с `nc -u -p 5000 <IP КРИСС> 5000` становится удалённым терминалом.

### Что не работает

- TCP (FE 72): прошивка 4.67 собирает битые сегменты и не хранит состояние, так что ни одна программа им пользоваться не может. Ядро такие кадры отбрасывает.
- Кадры не-IP, «сырой» Ethernet, кадры на чужие MAC: у модуля есть только сокеты.
- Доступ к КРИСС из-за NAT — только средствами роутера.
- Контрольная сумма UDP — 0 (как в 4.67). Не больше 726 байт данных в датаграмме (буфер кадра КРИСС — 768 байт); одновременно открыто не больше 5 своих портов (самый старый закрывается).
- Датаграммы приходят только с момента, когда программа задействовала свой порт: ядро открывает соединение, когда используется `PORT_MY` (FE 48 / 49 / 55 / 56 / 66 / 69) или канал переключается на сеть.

### Внутри

- `src/rtl/criss_esp.v` — UART к модулю: 115200 8N1, приёмный буфер 2 КБ, CTS к модулю (AT-прошивка работает с аппаратным управлением потоком).
- `src/fw/esp.c` — AT-движок. Никогда не блокирует: один разборщик принимает каждый байт (строки, приглашение `>`, `+IPD` с данными, которые могут прийти посреди любого ответа), в работе одна команда с тайм-аутом, остальные ждут в очереди. При запуске: `AT` до ответа, `ATE0`, закрыть все соединения, `AT+CIPMUX=1`, `AT+CIPDINFO=1`, `AT+CIFSR`. Перезапуск модуля (`ready`) или три тайм-аута начинают всё заново. Одно UDP-соединение на свой порт: `AT+CIPSTART=<n>,"UDP","0.0.0.0",0,<порт>,2` (слушать всех), отправка — `AT+CIPSEND=<n>,<длина>,"<ip>",<порт>`.
- `src/fw/net.c` — сторона КРИСС: банк FA / FB, буфер кадра, команды FE, разбор отправленных кадров, сборка принятых, классификация 4.67 (0x81–0x8B), каналы CP/M.

## Как устроено ядро

```
          SD-карта (файлы)          USB-клавиатура / мышь / порт
                │                               │
   МК платы (RP2040) ── связь (kg_mcu2) ── OSD, образы, PS/2, порт 0, часы
                │
   ┌────────────┴───────────── ПЛИС ─────────────────────────────┐
   │  T80 Z80 4,17 МГц ── SRAM 64 КБ (ОЗУ Z80, F800+ = экран)    │
   │     │ ED xx / IN / OUT: Z80 стоит (WAIT)                    │
   │  помощник VexRiscv RV32IM 75 МГц ── SDRAM (программа, ПЗУ)  │
   │     │ MMIO: регистры / ОЗУ Z80, видео, порты, SD, UART      │
   │  criss_video 640×480 ── OSD ── HDMI / VGA                   │
   │  criss_esp UART ── ESP8266                                  │
   └─────────────────────────────────────────────────────────────┘
```

- **Z80** (T80) выполняет CP/M КРИСС из своих 64 КБ ОЗУ в SRAM платы. Оригинальная прошивка обслуживает BIOS через коды `ED xx`, а все порты ввода-вывода — программно. В ядре `criss_z80.v` останавливает Z80 (WAIT) на таком коде и на каждом `IN` / `OUT`, и работу делает вспомогательный процессор: читает и пишет регистры и ОЗУ Z80, затем отпускает его. Прерывания получают вектор от помощника, подтверждаются аппаратно.
- **Помощник** — софт-процессор VexRiscv RV32IM (из core-doom) с кэшами. Его программа (`src/fw`, C) и ПЗУ данных (загрузочный образ CP/M, шрифты, таблицы клавиатуры и совместимости прошивок КРИСС) — два ПЗУ `.kg`, загружаются в SDRAM. Он играет роли контроллеров ЦПУ, периферии, VGA и цвета КРИСС: BIOS, консоль со всеми ESC-кодами и платформами, клавиатура, таймеры, мелодии, часы, мышь, RS-232, NVRAM, снимки, сеть.
- **Видео** (`criss_video.v`) читает экран КРИСС (ОЗУ Z80 с F800, туда же пишет помощник для ESC | ), 8 шрифтов и память цвета и выдаёт 640×480 при 60 Гц: знакоместа 8×20 / 19 / 16 / 15 точек по режиму, курсор, цвета модуля CLR.
- **Дискеты и NVRAM** — файлы образов, которые подключает прошивка платы (слоты `kg_l2_img`: A 0, B 1, NVRAM 4); `criss_sd.v` отдаёт помощнику секторы по 512 байт.
- **Обвязка платы** (`modules/`: связь `kg_mcu2` v2, наложение OSD, HDMI, PLL, звук) — общий репозиторий karabas-go-modules.

Прошивка помощника запускается и на ПК (`src/fw/host`): те же файлы на C, только вместо ПЛИС — интерпретатор Z80. Все тесты консоли, портов и сети идут там за секунды.

## Сборка

Нужны: Xilinx ISE 14.7 (`/opt/Xilinx/14.7`), xPack RISC-V GCC (`riscv-none-elf-gcc` 15.2, путь — в `src/fw/Makefile`), Python 3, `git submodule update --init`.

```
cd src
make fw          # прошивка помощника (fw/build/criss_fw.bin)
make roms        # ПЗУ данных из upstream/ (их скачивает tools/fetch_upstream.sh)
make minig       # одна плата: XST, map, PAR, bitgen, затем criss.kg
make             # все платы (go, mini, minig) и criss.kg
make minig-report
make nvr         # пустой образ NVRAM
```

`make` упаковывает в `criss.kg` все уже собранные платы. После правки верхнего модуля Mini G нужно запустить `python3 tools/mktops.py` для Go / Mini.

## Отличия от оригинала

Ядро повторяет прошивку 4.67 во всём, что видят программы, кроме:

- Z80 настоящий (T80) на 4,17 МГц: команды ведут себя как у микросхемы, а не как у эмулятора на AVR.
- Исправлены ошибки 4.67: `MUL` (`ED 77`), FF 39 (UART1 отправлял не тот байт), ESC g, переполнение сетевого буфера (FE 50 > 768 байт), обрезка датаграмм до 22 байт в каналах CON / READER.
- Режимы на 64 колонки показывают все 64 колонки.
- Системной консоли нет: вместо неё OSD и `nvrset.py`. Настройки, ОЗУ часов и снимки — файлы (`.nvr`) на SD-карте, дискеты — файлы `.cpm`.
- Сеть — через ESP8266 (выше).

Оставлено как в 4.67 намеренно: видимые особенности консоли (очистка экрана и смена режима по старой границе, прокрутка от символа в углу, ESC Z берёт ширину из A, неизвестная ESC съедает 5 байт, …), один регистр клавиши (при быстром наборе клавиши могут теряться, как на КРИСС).
